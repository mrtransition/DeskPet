# 宠物右键菜单与交互规范

> 适用版本：DeskPet 2.1.4+
> 关联需求：FR-PET-004（拖动与位置记忆）、FR-REM-004（免打扰）、FR-SYS-001（宠物右键菜单入口）
> 实现位置：`src/pet.html`、`src/shared.js`、`src-tauri/src/main.rs`
> 验收用例：AC-026

## 1. 目标与范围

本文档定义宠物窗口上的三类高频交互，避免后续改动破坏既有手感：

1. **右键菜单**：结构、排序、定位、开合与外部点击收起；
2. **睡眠与免打扰**：睡眠状态、点击唤醒、菜单勾选同步；
3. **拖动**：拖动阈值、系统拖动结束检测、位置持久化与状态恢复。

不在本文档范围内：气泡窗口的定位与关闭、设置页表单、托盘原生菜单、皮肤包格式（见 [`皮肤与图集规范.md`](皮肤与图集规范.md)）。

## 2. 右键菜单结构

宠物右键菜单为**单层平铺**，不使用二级子菜单。默认顺序如下：

| 顺序 | 菜单项 | 说明 |
|---|---|---|
| 1 | 💬 打开对话 | 收起菜单后打开气泡 |
| 2 | ✨ 新会话 | 打开气泡并请求清空当前会话 |
| 3 | — | 分隔线 |
| 4 | 皮肤（N） | 分组标题；内置皮肤、导入皮肤、导入/管理入口都在此组 |
| 5 | — | 分隔线 |
| 6 | ⚙ 设置 | 收起菜单后打开设置窗口 |
| 7 | 🌙 免打扰（睡眠） | 当前开启时显示 `✓`；切换后宠物进入/退出 `sleep` |
| 8 | 📍 复位宠物位置 | 收起菜单后把宠物移回默认位置 |

### 2.1 皮肤分组

- 内置皮肤固定显示在前，导入皮肤按皮肤库顺序排列；
- 当前皮肤显示 `✓`；导入皮肤额外显示类型标签（皮肤包 / Codex / 单图）；
- 皮肤数量较多时，**只让皮肤分组滚动**，上方「打开对话 / 新会话」和下方「设置 / 免打扰 / 复位位置」始终可见；
- 皮肤分组为空时显示占位符，不隐藏「导入 / 管理皮肤」入口。

### 2.2 菜单文案与状态

- 所有界面文案通过 `t()` / i18n 词条渲染，中英文即时切换；
- 勾选状态只读取当前真实状态：`S.settings.dnd`、`S.settings.activeSkin` / `S.settings.skin`；
- 菜单项点击后先关闭菜单，再执行动作，避免动作执行期间菜单残留。

## 3. 定位与窗口布局

菜单不是独立窗口，而是宠物窗口临时扩展后渲染的 HTML 菜单。定位由后端与前端共同保证：

### 3.1 后端 `pet_menu_layout`

1. 读取宠物窗口当前的屏幕物理位置、尺寸、DPI 与所在显示器工作区；
2. 以宠物屏幕位置为锚，计算窗口需要扩展到的宽高；
3. 优先把菜单放在宠物**右侧**；右侧空间不足时放**左侧**；两侧都不足时选择空间更大的一侧；
4. 窗口位置与尺寸夹紧在当前显示器工作区内，避免盖住任务栏或越出屏幕；
5. 返回窗口尺寸、宠物在窗口内的偏移、菜单所在侧与可用 bounds。

### 3.2 前端 `showMenu` / `menuPlace`

- 菜单与宠物之间保留 `MENU_GAP = 8px`；
- 菜单竖直方向与宠物居中对齐；
- 横向优先使用后端选定的侧；该侧仍放不下时自动翻到另一侧，最后才夹紧；
- 菜单最大宽度 300px；高度受工作区限制，超出的部分交给滚动容器；
- 菜单打开/关闭前后，**宠物在屏幕上的位置保持不变**，不允许出现角色跳动。

### 3.3 窗口状态约束

- 菜单态 `grown = true`、`menuOpen = true`；
- 菜单态触发 `onMoved` 时不把放大窗口的位置写回宠物位置；
- 菜单态触发 `onResized` 时忽略，尺寸由 `pet_menu_layout` 统一管理；
- 关闭菜单时使用 `pet_resize_keep`，以宠物屏幕位置为锚还原为 `120 × 112 × petScale`；
- 菜单打开前若迷你气泡已让窗口变大，先 `shrink()` 再按真实宠物位置布局。

## 4. 打开与关闭

### 4.1 打开

- 在宠物元素上触发 `contextmenu`；
- 若当前已有菜单打开，直接忽略，避免重复布局；
- 若迷你气泡展开，先收起；
- 完成布局后渲染菜单，并启动外部点击监听。

### 4.2 关闭

菜单在以下任一情况关闭并还原窗口：

| 触发 | 处理 |
|---|---|
| 点击菜单项 | `hideMenu()` 后执行动作；大多数动作调用 `shrink()` |
| 点击窗口内、菜单外的透明区域 | 前端 `document.mousedown` 捕获并 `shrink()` |
| 点击宠物本身 | 宠物点击流程在 `onPetUp` 中 `shrink()` |
| 点击其他软件 / 桌面 / 任务栏 | 后端外部点击监听发送 `pet-outside-click`，前端收起 |
| 宠物缩放变化 | `state-changed` 中先 `hideMenu()` 再 `shrink()` |
| 其他需要收起菜单的流程 | 统一调用 `shrink()`；`shrink()` 会停止外部点击监听 |

> 当前版本未提供 `Esc` 关闭和键盘方向键导航，见第 9 节已知限制。

## 5. 睡眠与免打扰

### 5.1 状态来源

- `S.settings.dnd = true` 时，宠物进入 `sleep` 状态；
- 后端 `set_dnd` 更新状态并广播 `dnd-changed`；
- 前端 `dnd-changed` 监听器同步 `S.settings.dnd`，并切换 `sleep` / `idle`。

### 5.2 点击唤醒

点击睡眠中的宠物视为**唤醒**：

1. 本地先把 `S.settings.dnd = false`；
2. 宠物状态从 `sleep` 切到 `idle`；
3. 调用后端 `set_dnd({ on: false })`；
4. 后端关闭免打扰、补发排队提醒，并广播 `dnd-changed`；
5. 右键菜单再次打开时，免打扰项不再显示 `✓`。

### 5.3 菜单内切换

菜单内点击免打扰项时：

- 先计算目标值并立即更新本地 `S.settings.dnd`；
- 立即切换宠物 `sleep` / `idle` 状态；
- 收起菜单后调用 `set_dnd`，由后端持久化并广播；
- 不做「只改视觉、不改状态」的临时切换，保证菜单勾选、宠物状态与持久化状态三者一致。

## 6. 拖动与状态恢复

### 6.1 拖动判定

- 只响应鼠标左键；
- 按下后移动距离超过 `6px` 才进入拖动，避免普通点击误触；
- 进入拖动时播放 `drag` 状态，并调用 `curWin.startDragging()`。

### 6.2 系统拖动结束检测

Windows 上 `startDragging()` 通过 `PostMessageW(WM_NCLBUTTONDOWN)` 进入系统模态拖动循环，前端不保证收到 `mouseup`。因此：

- 拖动开始后每 `60ms` 调用 Rust `mouse_left_down`（`GetAsyncKeyState(VK_LBUTTON)`）；
- 检测到左键已释放时，清理 `dragInfo`、`mousemove` / `mouseup` 监听与轮询定时器；
- 若当前仍是 `drag` 状态，立即恢复 `idle`，无需用户再点击一次。

### 6.3 位置持久化

- 非菜单/非气泡态下，`onMoved` 防抖 `600ms` 后调用 `pet_save_pos`；
- 菜单态与迷你气泡态不保存窗口位置，避免把临时放大位置写成宠物位置；
- 重启后从 `settings.petPos` 恢复。

## 7. 外部点击收起

### 7.1 为什么需要后端监听

前端 `document.mousedown` 只能收到宠物窗口内部的点击。用户点击其他软件、桌面或任务栏时，宠物窗口收不到事件，菜单会一直停留。

### 7.2 实现

- 菜单打开后调用 `pet_outside_watch_start`；
- Rust 记录当前宠物窗口的物理 bounds，启动后台线程，每 `12ms` 采样：
  - 左键是否按下（`GetAsyncKeyState(VK_LBUTTON)`）；
  - 光标是否在宠物窗口外（`GetCursorPos`）；
- 同时满足时向宠物窗口发送 `pet-outside-click` 事件，然后线程退出；
- 前端收到事件后 `hideMenu()` + `shrink()`；
- 菜单关闭时调用 `pet_outside_watch_stop`；
- 使用 generation 令牌区分不同次菜单打开，避免旧的 stop 误杀新菜单的监听；
- 启动期间菜单已关闭时，`startOutsidePoll` 会立即停掉刚启动的监听，避免遗留后台线程。

### 7.3 与窗口内点击的分工

- 窗口内、菜单外：前端 `document.mousedown`；
- 菜单项内部：不关闭，交给菜单项 `onClick`；
- 窗口外：后端监听；
- 三者互不重复触发，避免菜单点击被误判为外部点击。

## 8. 多显示器、缩放与 i18n

| 场景 | 行为 |
|---|---|
| 多显示器 | 以宠物中心所在显示器的工作区为边界；菜单不跨出该工作区 |
| 宠物缩放 0.5–2.0 | 宠物与窗口按缩放调整；菜单字号与宽度不随宠物缩放，避免小宠物配超大菜单 |
| 菜单过高 | 皮肤分组滚动，固定项保持可见 |
| 菜单过宽 | 先尝试翻到宠物另一侧，仍放不下时夹紧到工作区 |
| 中英文切换 | 菜单文案即时切换；菜单宽度随文案自适应，不影响定位约束 |
| 点击穿透 | 点击穿透开启时宠物不接收右键；需先通过托盘或快捷键恢复交互 |

## 9. 已知限制

- 菜单不支持 `Esc` 关闭；
- 菜单不支持键盘方向键 / Tab 导航与屏幕阅读器语义（`NFR-UI-004` 仍未实现）；
- 菜单为 HTML 渲染，不提供原生菜单的系统级无障碍能力；
- 外部点击监听仅在菜单打开期间运行，不注册全局鼠标钩子，因此不会影响其他应用；
- 当前宠物菜单不使用二级子菜单；`shared.js` 仍保留通用子菜单能力，供其他页面复用。
