# v2.3.2 — 修复演示模式对话误报 401

> 发布日期：2026-11-16
> 基线：v2.3.1
> 归档：本文件；GitHub Release 正文与本文件保持一致

## 摘要

v2.3.1 为「配好了却还在演示模式」引入的自动切换存在一个回归：只看 BaseURL，不看是否配置了 API Key，默认数据里预置的模板供应商（DeepSeek / OpenAI）会被当成可用的真实供应商。结果全新安装的演示模式第一句话就发出空 Key 请求，气泡显示「认证失败（401）」（服务端原文如 `Authentication Fails`）。本版本收紧自动切换条件，并让 401/403 给出可操作的下一步。

## 新增

- 本版本无新增能力；仅修复与错误提示增强。

## 修复

- **演示模式对话误报 401（FR-MDL-006 回归）**。触发条件：默认供应商仍是演示模式、会话绑定 `p-demo`，同时存在任意带 BaseURL 的真实供应商（默认状态内置的 DeepSeek / OpenAI 均未填 Key）。v2.3.1 的 `generate()` 用 `p.type !== 'mock' && p.baseUrl` 选中真实供应商并落盘，请求随即被服务端以 401 拒绝。
  - 现在只有「BaseURL 与模型名齐全、不是中文占位模板（如 Azure 的「你的资源名」）、且 `key_has` 确认已配置 Key」的云端供应商才参与自动切换；本地端点（Ollama / LM Studio 等）不自动切换，避免服务未启动时把演示对话变成连接失败。
  - 显式选择演示模式（`settings.mockPinned`）后不再自动切走，与 v2.3.1 的设计意图一致。
  - 旧版本遗留在「模板地址 + 空 Key」供应商上的会话 / 全局绑定，在发送前自动回到默认供应商（通常为演示模式），并用一次性系统消息说明原因；补全 Key 或设为默认后仍会正常切回。
  - 401/403 错误卡片在服务端原文之后追加「设置 → 模型检查 Key，或 ⚡ 菜单切回演示模式」的提示（FR-MDL-012）。
- **回归测试**：新增 `demo_mode_never_auto_switches_to_keyless_provider`，锁定「自动切换必须确认 Key」「本地端点与占位模板不参与」「`mockPinned` 优先」「旧实现不得回归」。

## 收敛与移除

- 本版本无功能移除。
- **收敛自动切换范围**：由「存在带 BaseURL 的真实供应商」收紧为「确实可用的真实供应商」；原因是该判定把演示模式变成了必然 401 的路径。
- **默认值变化**：无。演示模式仍是全新安装的默认供应商。

## 安全与隐私变更

- **密钥**：自动切换只通过 `key_has` 查询「是否已配置 Key」的布尔值，Key 本身仍只由主进程在发起请求时读取，不进入渲染层、日志与数据文件。
- **出站域名**：无新增；修复后演示模式不会再把消息发往未配置 Key 的云端模板。
- **授权 / 白名单**：无变化。
- **未完成事项**：更新包签名 / 哈希校验（NFR-SEC-004）仍未实现。

## 验证

- 自动化：`cargo test` 76 passed（新增 1 项演示模式切换回归）；`cargo build --release --target x86_64-pc-windows-gnu` 通过；`bubble.html` / `shared.js` 脚本 `node --check` 通过；`node scripts/check-governance.mjs` 通过。
- 手工路径（默认数据，无任何 Key）：点击小猫 → 输入任意消息 → 返回「（演示模式 · …）」内置回复，不再出现 401。
- 手工路径（已配置有效 Key 且默认仍是演示模式）：首条消息自动切到真实供应商并提示一次。
- 手工路径（在 ⚡ 里手动选演示模式）：后续消息保持演示模式，不被自动切走。
- 已知限制：未在真实 API Key 环境下重复做端到端请求验证（真实请求链路未改动，只改了供应商选择与错误提示）。

## 升级说明

- 无需手动操作；直接替换 `DeskPet.exe` 即可，数据文件与 Key 不受影响。
- 若在 v2.3.1 中已经被错误切到某个未填 Key 的供应商：升级后首次发送会自动回到演示模式并提示一次；想继续用真实模型，到「设置 → 模型」补全 Key 并勾选「设为默认」。

## 附注（对 v2.3.1 的勘误）

- v2.3.1 发布说明中「发送前若仍解析到演示模式且存在真实供应商，自动切换」的前提应补充为「存在确实配置了 Key 的真实供应商」；v2.3.2 已按此修正实现。
