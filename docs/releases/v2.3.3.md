# v2.3.3 — 更新包 SHA-256 与 Ed25519 校验

> 发布日期：2026-11-17
> 类型：安全补丁版
> 关联需求：NFR-SEC-004、FR-SYS-004、FR-SYS-009、AC-018
> 决策记录：TBD-04 选择 Ed25519

## 摘要

本版本补齐了长期挂起的 NFR-SEC-004：更新包不再只依赖 HTTPS，而是在保存到本地之前强制校验 **SHA-256** 与 **Ed25519 发布签名**。任一校验缺失或不匹配都会拒绝保存，当前版本继续可用。应用仍然只下载、不静默安装，校验通过后由用户手动运行安装包。

## 新增

- **更新包哈希校验**：自定义清单读取 `sha256`，GitHub Releases 读取 asset `digest` 或正文 `SHA256:` 行；下载完成后比对实际字节哈希，失败不写盘。
- **Ed25519 签名校验**：编译期内置公钥，签名对象为 SHA-256 的小写 hex 字符串；支持多公钥轮换，签名缺失或不匹配直接拒绝保存。
- **GitHub Release 校验行**：正文末尾的 `SHA256:` / `Ed25519-Signature:` 两行会被自动解析，无需额外网络请求。
- **发布工具链**：
  - `scripts/update-keygen.mjs` 生成 Ed25519 密钥对（私钥默认写入被忽略的 `.temp/`）；
  - `scripts/sign-update.mjs` 计算哈希、签名并写出 `.sha256` / `.sig` 旁车文件，同时输出可粘贴到 Release 正文的校验行。
- **文档**：新增[《更新安全》](../治理/更新安全.md)，覆盖清单格式、密钥管理、轮换、发布流程、验证与边界。
- **界面文案**：更新检查的中英文提示接入 i18n；缺少校验信息时展示原因并禁用下载按钮。

## 修复

- 更新检查在清单提供新版本但缺少校验信息时，不再显示可点击的下载按钮，避免用户下载无法验证的安装包。
- 校验失败不会留下半成品文件，`updates/` 目录只在双校验通过后写入。

## 收敛与移除

- 本版本无功能移除。
- 不再接受“仅 HTTPS、无哈希/签名”的更新清单用于下载；检查仍可展示版本信息，但不会提供下载入口。

## 安全与隐私变更

- **更新完整性**：下载前强制 SHA-256 + Ed25519 双校验；失败写 `update.verify_failed` 诊断日志（仅含哈希前 12 位与原因），成功写 `update.verified`。
- **密钥边界**：私钥不入库、不进入 CI 日志与发布产物；应用只内置 32 字节公钥，数组支持轮换。
- **出站域名**：无新增；默认仍为 `api.github.com`，校验信息随清单/Release 正文返回。
- **授权 / 白名单**：无变化。
- **未完成事项**：仍无 Authenticode 代码签名，Windows SmartScreen 可能提示未知发布者；更新仍不自动安装。

## 升级说明

- 直接替换 `DeskPet.exe` 即可，数据文件与 Key 不受影响。
- 从本版本开始，更新清单必须提供 `sha256` 与 `signature`（或 GitHub Release 正文对应行）；缺少时检查仍可用，但不会提供下载按钮。
- 自定义更新源若需继续分发，请使用 `scripts/sign-update.mjs` 为安装包生成校验值，并保留同一发布公钥。
