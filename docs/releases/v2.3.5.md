# v2.3.5 — 提醒补发策略

> 发布日期：2026-11-17
> 类型：可靠性补丁
> 关联需求：FR-REM-008、AC-025

## 摘要

本版本补齐 P1 的 FR-REM-008：明确应用退出、系统休眠、时区与夏令时（DST）变化后的提醒补发策略。错过提醒最多补发一次，默认只补发 24 小时内的提醒，用户可在设置中关闭补发或调整上限；重复提醒始终顺延到下一次未来时间，不会连续弹出历史内容。

## 新增

- **补发一次**：重启或休眠恢复后，同一提醒最多播报一次；已补发过的提醒不会再次进入队列。
- **明确上限**：默认 1440 分钟（24 小时），可配置 1–10080 分钟；超过上限的一次性提醒移除，重复提醒顺延。
- **可关闭**：设置 → 宠物与交互 → 提醒与免打扰新增「错过提醒后补发一次」开关与上限输入；关闭后仅播报 90 秒内视为准时的提醒。
- **时区 / DST 策略**：`due` 使用绝对时间戳，时区切换不改变到期时刻、不重复触发；每日 / 每周按固定绝对间隔推进，跨 DST 的墙体时间最多偏移 1 小时。
- **诊断日志**：新增 `reminder.skipped`（仅条数）与 `reminder.resume_gap`（仅中断秒数），不含提醒正文或系统信息。
- **用户文档**：新增[《提醒补发策略》](../提醒补发策略.md)。

## 修复

- 修复重启后可能补播很久以前提醒、造成批量打扰的问题。
- 修复关闭补发后重复提醒仍会播报历史内容的问题；现在会跳过播报并正确顺延。
- 正常运行的秒级调度抖动不受补发开关影响，避免误跳过准时提醒。

## 收敛与移除

- 本版本无功能移除。
- **不改变默认提醒方式**：补发默认开启，但仅限 24 小时内；超过上限的内容直接跳过。
- 免打扰队列仍只在内存中保存，应用退出后不恢复，避免重复播报。

## 安全与隐私变更

- **出站域名**：无新增；提醒调度完全本地执行，不产生网络请求。
- **数据与日志**：仅新增两个设置项 `settings.reminderCatchUp` / `settings.reminderCatchUpMin`；日志只记录跳过条数与中断秒数。
- **权限 / 授权**：无变化；不新增系统权限、工具或感知源。
- **未完成事项**：
  - 仍无 Authenticode 代码签名，Windows SmartScreen 可能提示未知发布者；
  - NFR-UI-004（键盘 / 读屏）与 NFR-UI-002（字体缩放 / 高对比度）仍未系统适配；
  - 未提供按提醒单独配置补发策略的能力。

## 验证

- 自动化：`cargo test` 84 passed（新增 2 个补发测试，覆盖上限内补发、超限跳过、关闭补发与秒级抖动）。
- 构建：`cargo build --release --target x86_64-pc-windows-gnu` 通过。
- 脚本：`src/settings.html` 内联脚本与 `src/i18n.js` / `src/shared.js` 语法检查通过。
- 待手工验收：创建 1 分钟后提醒 → 退出应用 → 2 分钟后重启 → 只播报一次；将提醒改为超过 24 小时过期 → 重启不播报；关闭补发后重复第一步 → 不播报。
- 已知限制：未在真实休眠 / 跨时区环境中做长时间观测；策略以绝对时间与 90 秒抖动容忍为基准。

## 升级说明

- 无需手动操作；直接替换 `DeskPet.exe` 即可，数据文件与 Key 不受影响。
- 旧数据缺少补发字段时按「开启 / 1440 分钟」处理，不迁移、不写回。
- 如需完全关闭补发，在设置中取消勾选即可，立即保存、下次调度生效。
