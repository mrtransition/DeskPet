> 规范：[发布说明规范](../治理/发布说明规范.md)

> 维护方式：每个对外版本新增 `vX.Y.Z.md`；发布后不再修改历史内容，勘误以附注追加

## 为什么单独归档

README 的版本历史适合快速浏览，但不适合承载完整的“新增 / 修复 / 收敛 / 安全 / 验证”。本目录保存每个版本的完整发布说明，并与 GitHub Release 正文保持一致，便于：

- 用户升级前核对影响；
- 贡献者理解某个功能的引入与移除原因；
- 维护者复盘默认值与安全边界的变化。

## 命名与内容要求

- 文件名：`v<主>.<次>.<修订>.md`，与 `src-tauri/tauri.conf.json` 的 `version` 一致；
- 必须包含：摘要、新增、修复、收敛与移除、安全与隐私变更、验证、升级说明；
- “收敛与移除”无内容时写“本版本无”，不得删除章节；
- 安全事项引用对应的 `INT-xxx` 评审记录；
- GitHub Release 正文与归档文件保持一致，不出现两个事实来源。

## 自动校验

`node scripts/check-governance.mjs` 会检查本目录下每个 `.md` 是否包含必需章节，并在 CI 中运行。
