> **需求用语约定**
> - **应（shall）**：强制需求，未实现即为缺陷。

## 1. 引言

### 1.1 编写目的

本文档完整定义「桌面 AI 宠物」软件的全部需求，包括功能需求、外部接口需求、性能需求、设计约束、系统属性、数据需求与验收准则。文档自包含：阅读者无需参考其他文档即可理解产品边界、每条需求的含义与验证方式。预期读者为产品负责人、架构师、开发工程师、测试工程师、项目验收方与运维人员。

### 1.2 产品标识与范围

**产品定义**：一款常驻桌面操作系统的 AI 交互应用。以「桌面宠物」形态呈现于屏幕之上，用户单击宠物即在宠物旁弹出微小气泡对话框，与用户自行配置的大语言模型进行多轮对话。软件本身不提供模型算力，仅作为模型服务的客户端与交互外壳。

**范围内（In Scope）**

| 编号 | 范围项 |
|---|---|
| S-01 | 宠物窗口：透明无边框置顶显示、动画状态机、拖拽、缩放、点击穿透、托盘驻留 |
| S-02 | 气泡对话框：点击触发、智能定位、流式对话、会话保持、快捷动作 |
| S-03 | 模型配置：多供应商接入、自定义 BaseURL、参数配置、密钥安全存储、连通性测试、快速切换 |
| S-04 | 人格管理：System Prompt 卡片、内置模板、导入导出、与皮肤/模型绑定 |
| S-05 | 数据持久化：供应商、人格、会话、消息、记忆、提醒、设置的本地存储与导出 |
| S-06 | 增强能力：长期记忆、工具调用、提醒/番茄钟、主动搭话、剪贴板感知、皮肤包、语音 |
| S-07 | 系统集成：托盘、全局快捷键、开机自启、自动更新、用量统计 |

**范围外（Out of Scope）**

| 编号 | 排除项 | 说明 |
|---|---|---|
| O-01 | 模型训练、微调与算力提供 | 由外部模型服务承担 |
| O-02 | 云端账号体系与云端数据存储 | v1 为纯本地应用，无自建服务端 |
| O-03 | 移动端（iOS/Android）与 Web 端 | 后续版本规划 |
| O-04 | 多人协作、社交分享服务端 | 仅预留配置文件格式 |
| O-05 | 任意 Shell 命令执行 | 明确禁止，见 NFR-SEC-002 |

**典型使用场景（用于理解需求上下文）**

| 场景 | 描述 | 关联需求 |
|---|---|---|
| SC-01 随手问 | 工作中遇到问题，单击宠物 → 气泡内提问 → 流式回答 → Esc 关闭，全程不切换主窗口 | FR-BUB-001/006/008/013 |
| SC-02 情绪陪伴 | 宠物按配置频率主动冒出一句，用户回一句吐槽 | FR-REM-005 |
| SC-03 定时提醒 | 「20 分钟后提醒我喝水」，到点宠物播报并支持稍后提醒 | FR-REM-001/002 |
| SC-04 剪贴板助手 | 复制一段英文后，宠物旁提示「要翻译吗」，点击即处理 | FR-REM-007 |
| SC-05 本地模型 | 配置 Ollama，全程离线完成对话 | FR-MDL-001/003、NFR-CON-005 |
| SC-06 模型切换 | 日常用轻量模型，复杂问题在气泡内一键切换到强模型 | FR-MDL-005/006 |
| SC-07 人格切换 | 工作时间用「专注搭子」，休息时切到「毒舌吐槽役」 | FR-PSN-003 |

### 1.3 术语与缩略语

| 术语 | 定义 |
|---|---|
| 宠物窗口 | 承载角色形象的透明、无边框、默认置顶窗口 |
| 气泡对话框 | 单击宠物后弹出的无边框小型对话窗口，是本产品核心交互载体 |
| 供应商（Provider） | 一类大模型服务的接入配置，如 OpenAI、Ollama、自定义 OpenAI 兼容端点 |
| 人格（Persona） | 一组「System Prompt + 开场白 + 快捷动作 + 绑定模型 + 音色」的组合配置 |
| 快捷动作（Quick Action） | 气泡内预置的按钮式指令，点击即以预设内容发送 |
| 流式输出（Streaming） | 模型以增量 token 方式逐段返回结果，前端逐字呈现 |
| 上下文（Context） | 发送给模型的会话消息序列 |
| 长期记忆（Long-term Memory） | 跨会话持久化的用户事实条目，按相关度注入 System Prompt |
| 工具调用（Function Calling） | 模型输出结构化调用请求，由客户端执行本地函数并回传结果 |
| 人格卡片 / 皮肤包 | 用户可导入导出的配置包与动画资源包 |
| 免打扰（DND） | 静音所有主动提醒并使宠物进入休眠状态 |
| 工作区（Work Area） | 当前显示器去除任务栏/菜单栏后的可视矩形区域 |
| DPI | 每英寸像素数，用于高分辨率屏幕缩放适配 |
| SSE | Server-Sent Events，服务端流式推送协议 |
| ASR / TTS | 语音识别 / 语音合成 |
| 首 token 延迟 | 从请求发出到收到第一个 token 的时间 |
| 密钥引用（Key Ref） | 数据库中指向系统安全存储条目的标识，非密钥本身 |

## 2. 总体描述

### 2.1 产品视角

本系统为**单机独立桌面应用**，通过操作系统能力（窗口管理、托盘、全局快捷键、安全存储、剪贴板、通知）实现交互，通过网络调用外部大模型服务（云端 API 或本地推理服务）。系统不依赖自建服务端，可在完全离线环境下运行全部非对话功能。

```
┌────────────────────────────── 用户桌面 ──────────────────────────────┐
│                                                                      │
│  ┌──────────────┐   单击    ┌────────────────┐   IPC    ┌──────────┐  │
│  │  宠物窗口     │ ───────▶ │  气泡对话框     │ ◀──────▶ │  主进程   │  │
│  │ 透明/置顶/动画│ ◀─────── │  无边框/小尺寸  │          │ (Tauri)  │  │
│  └──────────────┘  状态机   └────────────────┘          └────┬─────┘  │
│                                                              │        │
│  ┌──────────────┐        ┌────────────────┐                 │        │
│  │  设置窗口     │ ◀───── │  系统托盘/快捷键 │                 │        │
│  └──────────────┘        └────────────────┘                 │        │
│                                                              │        │
│  ┌──────────────────────────────────────────────┐           │        │
│  │ 本地存储：SQLite（业务数据） + 系统安全存储（密钥）│ ◀─────────┘        │
│  └──────────────────────────────────────────────┘                    │
└──────────────────────────────────────────────────────────────┬───────┘
                                                               │ HTTPS / SSE
                                                     ┌─────────▼─────────┐
                                                     │ 大模型服务          │
                                                     │ 云端 API / 本地服务 │
                                                     └───────────────────┘
```

**关键架构性约束（影响需求实现方式，非实现方案）**：模型请求与密钥管理必须位于主进程侧，气泡窗口作为独立窗口承载交互——这两点由 NFR-INT-001、FR-MDL-013 约束，属需求而非设计选择。

### 2.4 运行环境

| 项 | 要求 |
|---|---|
| 操作系统 | Windows 10 1903+ / Windows 11（首发）；macOS 12+；Linux（X11 优先，后续版本） |

### 2.5 设计与实现约束

| 编号 | 约束 |
|---|---|
| CON-01 | 应用应支持无管理员权限安装与运行 |
| CON-02 | API Key 不得明文持久化，不得写入任何日志文件 |
| CON-03 | 应用不得执行任意 Shell 命令；工具调用须白名单化并经用户授权 |
| CON-04 | 宠物窗口与气泡窗口应支持多显示器与高 DPI 缩放 |
| CON-05 | 除对话外的全部核心功能（宠物呈现、设置、提醒、历史、记忆管理）应在离线状态下可用 |
| CON-06 | 核心业务逻辑应与平台相关能力解耦，以支撑多平台构建 |
| CON-07 | 密钥管理与网络请求限定在主进程侧，渲染层不得直接持有密钥 |
| CON-08 | 单一模型/网络异常不得导致进程整体崩溃 |

### 2.6 假设与依赖

| 编号 | 假设/依赖 | 影响 |
|---|---|---|
| ASM-01 | 用户可自行获取目标模型服务的 API Key 或本地服务地址 | 若无法获取，对话功能不可用，但宠物与设置功能仍可用 |
| ASM-02 | 操作系统提供窗口置顶、托盘、全局快捷键与安全存储能力 | 若某平台缺失（如部分 Linux 环境无安全存储），需降级方案（见 TBD-02） |
| ASM-03 | 外部模型服务遵循其公开 API 规范 | 供应商接口变更由供应商负责，客户端需具备错误降级（FR-MDL-012） |
| ASM-04 | 用户系统时间准确 | 提醒功能的准确性依赖系统时钟 |

## 3. 具体需求

### 3.1 功能需求

#### 3.1.1 宠物窗口与呈现（FR-PET）

| 编号 | 需求描述 | 优先级 | 验证 |
|---|---|---|---|
| FR-PET-001 | 系统**应**提供无边框、背景完全透明的宠物窗口，窗口尺寸随角色包围盒自适应。 | P0 | D |
| FR-PET-002 | 宠物窗口**应**默认始终置顶，并**应**支持配置置顶层级（普通 / 置顶 / 置顶且覆盖任务栏）。 | P0 | T |
| FR-PET-003 | 宠物窗口默认**不应**显示在任务栏或程序坞，该行为**应**可配置。 | P0 | T |
| FR-PET-004 | 用户**应**可通过长按拖动移动宠物；松手后位置**应**持久化，重启后恢复至原位置。 | P0 | T |
| FR-PET-005 | 系统**应**支持宠物跨多显示器拖动并记录所在屏幕；当分辨率或显示器拓扑变化时，宠物**应**自动回收至可视工作区内。 | P1 | T |
| FR-PET-006 | 系统**应**提供动画状态机，至少包含 `idle`、`drag`、`click`、`talk`、`sleep`、`work`、`happy`、`error` 八种状态，并**应**支持状态间平滑切换。 | P0 | D |
| FR-PET-007 | 系统**应**支持 50%–200% 无级缩放并持久化该设置。 | P1 | T |
| FR-PET-008 | 系统**应**支持点击穿透模式；开启后鼠标事件穿透至下层窗口，用户**应**可通过托盘或全局快捷键恢复交互。 | P1 | T |
| FR-PET-009 | 系统**应**至少支持 APNG 与 GIF 动画格式；**宜**支持 Live2D Cubism 4、Spine、Lottie、帧序列。 | P0 | I |
| FR-PET-010 | 当宠物处于非 `idle`/`talk` 状态且用户无交互时，系统**宜**将动画帧率降至 30fps 以降低资源占用。 | P1 | A |

#### 3.1.2 点击触发与气泡对话框（FR-BUB）

| 编号 | 需求描述 | 优先级 | 验证 |
|---|---|---|---|
| FR-BUB-001 | 用户单击宠物时，系统**应**在 300 ms 内于宠物附近弹出气泡对话框，并同步播放 `click` 动画。 | P0 | T |
| FR-BUB-002 | 气泡对话框**应**为无边框窗口，包含指向宠物的视觉指示（尾巴或箭头），并**应**采用圆角与半透明磨砂样式。 | P0 | D |
| FR-BUB-003 | 气泡宽度**应**默认可在 280–360 px 自适应，用户**应**可拖拽边缘调整至 240–480 px；高度**应**自适应 80–360 px，超出时**应**可滚动。 | P1 | T |
| FR-BUB-004 | 气泡定位**应**采用智能翻转：优先显示于宠物上方，上方空间不足时显示于下方；水平方向**应**夹紧于当前屏幕工作区内。 | P0 | T |
| FR-BUB-005 | 拖动宠物时，已打开的气泡**应**跟随移动。 | P1 | T |
| FR-BUB-006 | 气泡输入框**应**在弹出后自动获得键盘输入焦点，且**不得**使其他应用窗口持续失去前台激活状态（与 NFR-INT-001 一致）。 | P0 | T |
| FR-BUB-007 | 气泡**应**支持三类消息渲染：用户消息、AI 消息（支持 Markdown、代码块语法高亮、一键复制）、系统提示消息（错误/提醒）。 | P0 | T |
| FR-BUB-008 | AI 回复**应**以流式方式逐 token 呈现，生成期间**应**提供「停止生成」控制。 | P0 | T |
| FR-BUB-009 | 输入区**应**为自适应多行输入框（1–4 行）；`Enter` 发送、`Shift+Enter` 换行，该行为**应**可配置。 | P0 | T |
| FR-BUB-010 | 气泡**应**展示可配置的 3–5 个快捷动作按钮，点击后**应**以预置指令直接发送。 | P1 | T |
| FR-BUB-011 | 系统**应**维护气泡内当前会话上下文，并提供「新会话」控制以清空上下文。 | P0 | T |
| FR-BUB-012 | 气泡关闭后会话**不应**丢失；默认下次打开**应**恢复上次会话，并**应**可配置为「每次点击新开会话」。 | P1 | T |
| FR-BUB-013 | 气泡**应**在下列条件之一时关闭：按 `Esc`、点击气泡外区域、窗口失焦、无交互闲置达到可配置时长（默认 60 s）。 | P0 | T |
| FR-BUB-014 | 生成期间系统**应**显示思考状态（Loading 指示 + `work` 动画）；请求失败时**应**在气泡内显示错误信息与重试入口。 | P0 | T |

## 4. 数据需求

### 4.1 数据实体与关系

| 实体 | 说明 | 关键属性 | 关联 |
|---|---|---|---|
| 供应商配置 | 一套模型服务接入配置 | 名称、类型、BaseURL、密钥引用、模型名、参数、代理、是否默认 | 1:N 人格 |
| 人格 | 对话角色配置 | 名称、头像、System Prompt、开场白、快捷动作、绑定供应商、绑定皮肤、音色 | 1:N 会话 |
| 会话 | 一次持续的对话线程 | 人格引用、标题、创建/更新时间 | 1:N 消息 |
| 消息 | 单条对话内容 | 角色（user/assistant/system/tool）、内容、token 数、时间 | 属于会话 |
| 记忆 | 长期事实条目 | 键、值、来源会话、创建时间 | 可选关联会话 |
| 提醒 | 定时任务 | 内容、触发时间、重复规则、启用状态 | — |
| 设置 | 键值配置 | 键、值 | — |
| 密钥 | 敏感凭据 | 仅存于系统安全存储，业务库仅存引用标识 | 被供应商配置引用 |

**关系约束**：
- 一个供应商配置可被多个人格引用；一个人格绑定一个供应商配置。
- 删除供应商配置时，若存在引用其的人格，**应**提示用户并禁止直接删除或要求重新绑定。
- 删除人格时，其历史会话**应**保留，但标记为「人格已删除」。

| DR-003 | 数据清理**应**在二次确认后执行，且**应**明确告知影响范围（是否含记忆、是否含配置）。 | P0 |
| DR-004 | 用户**应**可导出全部业务数据为可读格式（会话为 Markdown，配置为人格/供应商 JSON）。 | P1 |

| 编号 | 需求描述 |
