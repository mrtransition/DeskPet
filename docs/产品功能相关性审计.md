# DeskPet 产品功能相关性审计

> 审计对象：DeskPet 2.1.1 的功能与仓库快照（执行后基线：2.1.2）
> 审计日期：2026-11-10
> 判定基准：SRS 1.2 产品定义与 1.2.1 版本范围分层、README 产品定位、当前核心使用闭环
> 结论用途：识别与「桌面 AI 宠物」定位无关或越界的功能，为后续收敛、隐藏、移除或重新归类提供依据
>
> **执行状态（2026-11-10）**：P0 已落地于 DeskPet 2.1.2 / SRS v1.2——费用估算、出站审计 UI、自定义请求头、关于页 SRS 表已移除；重复 MVP 原型、未引用素材与构建残留已清理；健康/剪贴板与天气/搜索降级为默认关闭的实验性增强。P1/P2 中的隐私文案校准与更新检查默认策略仍待后续处理。

---

## 1. 结论摘要

1. **核心闭环是健康的**：宠物窗口、点击气泡对话、多模型接入、人格、记忆、提醒、皮肤/Codex、托盘与本地隐私，均直接服务于「桌面上有一只可聊天的 AI 宠物」。皮肤、八态单图与 Codex 契约属于强相关差异化，不应被误判为无关功能。
2. **真正与产品无关的是「开发者/运维面板」**：token 用量与费用估算、出站请求审计 UI、自定义请求头、代理配置。这些能力面向 API 调试、企业网络或计费管理，普通宠物用户不会使用，且会稀释产品叙事、增加安全面。
3. **范围膨胀主要来自「通用效率助手」**：久坐/喝水提醒、剪贴板感知、天气查询、联网搜索、打开应用/URL。它们可以增强陪伴感，但本质是通用桌面助手能力；其中健康与剪贴板增强在 SRS 1.2.1 中原本被归入 v3 Optional，却在 v2.0 提前交付，文档口径需要统一。
4. **隐私承诺与实际出站不一致**：README 声称「唯一的网络请求是你自己配置的模型 API」，但实际还存在天气、搜索、更新检查与更新下载请求；出站审计只覆盖对话与更新，不覆盖天气/搜索，容易给用户「已全部审计」的错觉。
5. **仓库层面存在非产品内容**：根目录保留了一份与 `docs/MVP-浏览器模拟版.html` 完全相同的原型副本，另有未引用设计素材、备份 exe、临时截图与旧代码片段。这些不属于产品功能，应清理或归档。

**总体判断**：当前实现中，约六成功能属于核心或直接增强，约两成属于工程/分发支撑，约两成属于应降级或移除的越界功能与非产品内容。建议下一阶段不继续扩展通用助手能力，优先做「减法」和口径校准。

## 2. 审计口径

### 2.1 产品定位

依据 SRS 1.2 与 README：

> 一款常驻桌面的 AI 交互应用。以「桌面宠物」形态呈现，用户单击宠物即在旁边弹出微小气泡，与用户自行配置的大语言模型多轮对话。软件本身不提供模型算力，仅作为模型服务的客户端与交互外壳。

核心闭环可以概括为：

```text
桌面上的宠物存在感
      ↓ 单击
气泡内轻量对话
      ↓ 持续使用
人格 / 记忆 / 提醒 / 皮肤形成陪伴感
      ↓ 长期留存
本地数据与隐私可控
```

### 2.2 判定等级

| 等级 | 定义 | 处置原则 |
|---|---|---|
| **A 核心相关** | 移除后核心闭环不成立，或直接决定「像不像一只桌面宠物」 | 保留并持续打磨 |
| **B 体验增强** | 服务于核心闭环的周边能力，但可被替代或关闭；过度扩展会稀释定位 | 保留但默认克制，不进入主卖点 |
| **C 工程/分发支撑** | 不是用户功能，而是构建、分发、安全、数据或质量保障 | 保留在工程与路线图中，不进入功能宣传 |
| **D 与产品无关/越界** | 主要面向开发者、企业或通用效率场景；移除后不影响核心闭环；或与产品承诺冲突 | 移除、隐藏或降级为高级诊断 |
| **E 当前版本之外** | 已登记但未实现，或明确属于 v3/v4 | 冻结，不投入当前版本 |

### 2.3 「无关」的判定标准

满足以下任一条即可判定为 D 类：

- 移除后不影响「宠物存在 → 点击对话 → 陪伴留存」的核心路径；
- 主要用户价值指向 API 调试、计费管理、企业网络或通用桌面自动化；
- 与产品对外承诺（零上报、密钥零泄露、轻量）直接冲突；
- 维护成本、安全面或解释成本明显高于用户价值；
- 属于内部验收、开发调试或仓库管理内容，而不是终端用户功能。

## 4. 重点问题详述

### 4.1 「费用估算」是典型的开发者功能

费用估算需要用户自己填写输入/输出单价，且 token 数由字符数估算（`est_tokens`），既不是账单数据，也不具备跨供应商可比性。它回答的是「我这次 API 调用大概花了多少钱」，而不是「我的宠物今天陪了我多久」。这类信息应属于 API 客户端或网关，不应占据桌面宠物的「关于」页。

**建议**：从关于页删除价格输入与费用行；若保留 token 统计，只作为隐藏诊断信息，不展示货币金额。

### 4.2 「出站审计」提供了不完整的安全感

当前审计只记录对话请求（`run_turn`）与更新请求（`update_check` / `update_download`），天气与搜索经由 `execute_tool` 直接发往 Open-Meteo 与 DuckDuckGo，**不会出现在审计列表**。用户看到「出站请求审计」时，会自然理解为所有出站都被记录，这与实际行为不符。

**建议**：要么补齐所有出站记录（包括工具），要么移除审计 UI，改为「隐私说明 + 日志文件」；后者更符合普通用户需求。

### 4.3 自定义请求头与「密钥零泄露」冲突

`headers` 字段随供应商配置保存到 `data.json`，并进入配置导出。若用户按企业网关习惯填入 `Authorization: Bearer …` 或 `x-api-key`，密钥就会以明文形式落盘，绕过 Windows 凭据管理器。这与 README 的「密钥零泄露」承诺直接冲突（SRS NFR-SEC-006 也仍标记为「部分」）。

**建议**：默认移除该输入项；确需支持时，识别敏感头并只保存凭据引用，导出时写占位符。

### 4.4 健康提醒、剪贴板感知与费用估算的版本归属自相矛盾

SRS 1.2.1 的 v3 Optional 明确包含「费用估算、健康/剪贴板增强」，但 3.1.11 又把 FR-SYS-005、FR-REM-006/007 列为 v1 可选 P2，并且这三项已在 v2.0/v2.1 实现。结果是：

- 产品文档一边说它们是 v3 可选，一边又按 v1 可选用户可见；
- 功能已经交付，但产品定位没有同步收敛。

**建议**：在产品口径上统一为「v2 已交付的周边增强，默认关闭/弱入口；v3 不再重复立项」，或在 SRS 中正式调整为 P2 并说明理由。

### 4.5 隐私文案与真实网络行为不一致

README 隐私表写的是：

> 无遥测、无埋点、无崩溃收集；唯一的网络请求是你自己配置的模型 API。

实际网络行为至少包括：

| 出站 | 目标 | 触发方式 | 是否计入审计 |
|---|---|---|---|
| 对话 | 用户配置的模型服务 | 用户发送消息 | 是 |
| 天气 | `geocoding-api.open-meteo.com`、`api.open-meteo.com` | 模型调用 `get_weather` 且用户授权 | **否** |
| 搜索 | `html.duckduckgo.com` | 模型调用 `web_search` 且用户授权 | **否** |
| 更新检查 | 默认 `api.github.com/repos/mrtransition/deskpet/releases/latest` | 打开设置页且开启自动检查 | 是 |
| 更新下载 | 更新清单中的 URL | 用户点击下载 | 是 |

**建议**：把文案改为「无遥测；除模型 API 外，仅在用户主动使用天气/搜索/更新时访问对应服务」，并在首次引导/隐私页列明域名。另需修正默认更新地址的仓库名大小写（`DeskPet`），避免 404。

### 4.6 关于页不是需求文档的展示位

关于页当前内嵌了完整的 SRS 覆盖对照表，包含大量「完整 / 部分 / 未实现」「P0/P1/P2/P3」字样。这些是内部验收语言，不是终端用户需要的信息。它还会导致每次需求状态变化都要同步改 HTML，增加发版负担。

**建议**：关于页只保留产品名、版本、许可、隐私说明、更新入口与项目链接；需求覆盖表迁回 `docs/`。

## 6. 不建议误删的核心功能

以下功能虽然「不直接等于一只猫」，但属于产品成立的必要条件，不应被本次审计误伤：

- 多模型接入与密钥管理：没有它，气泡只是空壳；
- 人格与长期记忆：决定「像宠物」而不是「像搜索框」；
- 提醒与主动搭话：决定桌面存在感与回访；
- 皮肤、八态单图、Codex 契约：决定外观可玩性与社区扩展；
- 托盘、快捷键、开机自启、位置记忆：决定「常驻桌面」而不是普通窗口应用；
- 本地数据与隐私说明：决定用户是否愿意长期使用；
- TTS：低成本、高陪伴感的增强，保留。

## 8. 最终建议

DeskPet 的竞争力在「桌面宠物 + 任意模型 + 可换皮肤 + 本地隐私」，不在「又一个通用 AI 助手」。当前功能面已经出现明显的助手化倾向：费用、审计、请求头、代理、天气、搜索、剪贴板、健康提醒层层叠加，而真正决定宠物感的皮肤、动画、人格、主动互动反而容易被淹没。

下一阶段最值得做的不是继续加功能，而是：

1. **把开发者面板移出用户界面**（费用、审计、请求头、代理、SRS 对照表）；
2. **把通用助手能力降为可选**（健康、剪贴板、天气、搜索），默认关闭、弱入口；
3. **把隐私与体积文案校准到真实行为**；
4. **把仓库清理到只保留产品、文档与示例**；
5. **继续投入皮肤、Codex、八态与人格互动**，这才是产品相关性最高、最难被通用助手替代的部分。

> 本文只做相关性判断，不替代 SRS 的范围裁决。涉及需求删除或优先级调整时，应在 SRS 变更记录中单独登记。
