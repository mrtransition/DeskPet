# 跨平台审慎评估（P-14）

> 状态：✅ 已完成（结论：短期维持 Windows 优先，不启动跨平台移植）
> 评估日期：2026-11-13
> 评估方式：维护者依据 v2.3.0 实现、`platform.rs` 适配层与 SRS 约束自评
> 关联：[DeskPet 后续开发规划文档](../DeskPet%20后续开发规划文档.md)、[隐私与安全白皮书](../治理/隐私与安全白皮书.md)、[ROADMAP](../ROADMAP.md)
> 决策有效期：至下一次重评触发条件出现

## 1. 结论摘要

**短期（未来 6—12 个月）不将 macOS / Linux 作为交付目标，继续以 Windows 体验完整性与稳定性为唯一优先级。**

理由：

1. 跨平台不是“编译通过”问题，而是透明窗口、置顶层级、托盘、全局快捷键、单实例、安全存储、开机自启、文件管理器定位等**一整套系统集成**的逐项重建；
2. 当前安全承诺（密钥只进 Windows 凭据管理器、单实例、剪贴板只读、工具白名单）均以 Windows 为基线，跨平台需要新的降级与评审方案；
3. 维护者与 CI 资源有限，三平台并行会直接稀释 Windows 核心体验的打磨；
4. P-10 已完成平台适配层抽象，跨平台能力作为**架构预留**保留，而不是产品承诺。

**重评不等于自动启动**：即使满足第 6 节条件，也需单独立项、单独评审、单独排期。

## 2. 现状盘点

### 2.1 已隔离到 `src-tauri/src/platform.rs`

| 能力 | 接口 | Windows 实现 | 非 Windows 行为 |
|---|---|---|---|
| 工作区计算 | `work_area_at` | `MonitorFromPoint` + `GetMonitorInfoW` | 固定 1920×1040 保守区域 |
| 剪贴板读取 | `clipboard_read_text` | Win32 剪贴板（仅纯文本） | 返回 `None` |
| 外部链接 | `open_external_url` | `rundll32 url.dll,FileProtocolHandler`，仅 http/https | 返回“尚未适配”错误 |
| 前台窗口 | `foreground_window` / `set_foreground` | `GetForegroundWindow` / `SetForegroundWindow` | 返回 0 / 空操作 |
| 鼠标左键 | `mouse_left_down` | `GetAsyncKeyState(VK_LBUTTON)` | 返回 `false` |
| 光标位置 | `cursor_pos` | `GetCursorPos` | 返回 `None` |
| 置顶层级 | `set_topmost` | `SetWindowPos(HWND_TOPMOST / NOTOPMOST)` | 空操作 |
| 单实例 | `acquire_single_instance` / `watch_second_launch` | 命名互斥量 + 命名事件 | 返回 `true` / 空操作 |
| 文件管理器定位 | `reveal_in_file_manager` | `explorer.exe /select,` | 返回“尚未适配”错误 |

依赖侧：`windows-sys` 已改为 `[target.'cfg(windows)'.dependencies]`；`keyring`、`tauri-plugin-autostart`、`tauri-plugin-global-shortcut`、`tauri`（`tray-icon`）本身为跨平台 crate。

### 2.2 仍与 Windows 绑定的部分

| 位置 | 现状 | 跨平台影响 |
|---|---|---|
| `open_whitelisted_app` | 白名单为 `notepad / calc / mspaint / explorer / snippingtool` | 其他平台需重新定义应用白名单与启动方式 |
| 单实例入口 | `main()` 中 `#[cfg(windows)]` 才调用 | 非 Windows 当前不做单实例约束 |
| 托盘 / 快捷键 / 自启 | 使用 Tauri 插件，但仅在 Windows 验证 | macOS 菜单栏、Linux AppIndicator 与 Wayland 行为需逐一验证 |
| 窗口能力 | `transparent` / `alwaysOnTop` / `skipTaskbar` | Linux 依赖合成器与窗口管理器；macOS 激活策略不同 |
| 应用图标 | `icons/icon.ico` | macOS 需要 `.icns`，Linux 需要多尺寸 PNG |
| 打包 | `bundle.active = false`，当前为便携目录分发 | 三平台需要各自的安装包、签名与更新链路 |
| 安全存储 | Windows 凭据管理器 | macOS Keychain 可用；Linux 需 libsecret / secret-service，且存在无安全存储环境（TBD-02） |
| 文档与承诺 | 白皮书适用范围写明“Windows 桌面版” | 跨平台前必须重写数据地图与威胁模型 |

## 3. 平台成本评估（估算，非承诺）

| 能力 | macOS | Linux（X11 优先） |
|---|---|---|
| 透明无边框窗口 | WKWebView 透明可用，需验证阴影与点击穿透 | 依赖合成器；无合成器时透明失效 |
| 置顶 / 覆盖全屏 | `NSWindow.level`，需处理全屏空间与多桌面 | 窗口管理器差异大，`always_on_top` 不保证覆盖任务栏 |
| 托盘 | 菜单栏图标与模板图标 | AppIndicator / StatusNotifier，依赖桌面环境 |
| 全局快捷键 | 需要辅助功能授权 | X11 grab；Wayland 需 portal，可能不可用 |
| 单实例 | 应用包通常天然单实例，需处理 `open -n` | 需 DBus 或锁文件方案 |
| 开机自启 | LaunchAgent | `.desktop` autostart |
| 剪贴板 | NSPasteboard，需处理隐私提示 | X11 / Wayland 剪贴板协议不同 |
| 安全存储 | Keychain（可用） | libsecret；无安全存储时需明确降级（TBD-02） |
| 打开链接 / 定位文件 | `open` / `open -R` | `xdg-open` / 文件管理器 DBus 接口 |
| 打包与签名 | 签名 + 公证（notarization） | AppImage / deb / rpm，签名策略待定 |
| 粗略工作量 | 3—5 人周（不含长期维护） | 4—8 人周（不含 Wayland 深水区） |

> 上述估算只覆盖“能跑起来”，不含三平台 CI、回归测试、文档、支持与安全评审成本。

## 4. 方案对比

| 方案 | 描述 | 收益 | 风险 / 成本 | 结论 |
|---|---|---|---|---|
| A. 立即跨平台 | 同步交付 macOS / Linux | 覆盖更多用户 | 核心体验被稀释、系统集成缺陷、支持负担 | ❌ 不采用 |
| B. 条件推进 | 满足第 6 节条件后，按 macOS → Linux 顺序立项 | 风险可控，保留架构预留 | 需要长期维护者与 CI 资源 | 🟡 未来可选 |
| C. Windows 优先 | 维持单一平台，持续打磨核心体验 | 聚焦、稳定、安全承诺可验证 | 放弃部分用户 | ✅ **当前采用** |

## 6. 重评触发条件

满足以下**全部**条件后，才重新评估是否启动跨平台：

1. Windows 版本连续两个发布周期无 P0 级缺陷，核心聊天、提醒、皮肤、工具链路稳定；
2. `platform.rs` 覆盖第 2.2 节全部待办项，业务代码无平台分支泄漏；
3. 具备 macOS / Linux CI 运行器与可复现构建，能阻止平台回归；
4. 明确签名 / 公证方案与更新包校验策略（含 NFR-SEC-004 的签名缺口）；
5. 完成 Linux 无安全存储环境的密钥降级方案（TBD-02）并通过安全评审；
6. 有至少一名可长期维护目标平台的贡献者，而非一次性移植；
7. 跨平台安全评审记录（托盘、快捷键、剪贴板、单实例等）已登记。

## 7. 风险与缓解

| 风险 | 表现 | 缓解 |
|---|---|---|
| 核心体验稀释 | Windows 细节打磨停滞 | 明确 Windows 优先；跨平台单独立项 |
| 平台差异缺陷 | 透明 / 置顶 / 托盘在某桌面环境失效 | 平台适配层 + 显式降级 + 平台 CI |
| 安全承诺失真 | 密钥、剪贴板、出站行为在新平台不同 | 重写威胁模型；逐项安全评审；不满足则不发布 |
| 维护成本失控 | 三平台 issue 与打包矩阵膨胀 | 设定最低维护者与 CI 门槛；不达标不启动 |
| Wayland 碎片化 | 快捷键 / 置顶 / 截图不可用 | X11 优先；Wayland 单独评估，不承诺等价能力 |

## 8. 验收与后续

- 本报告给出明确结论：**短期维持 Windows 优先，不启动移植**；
- 架构预留已通过 P-10 落地，并借本次评估补齐 `reveal_in_file_manager` 的平台隔离；
- 未新增工具、感知源或系统集成点，因此不新增 `INT-xxx` 记录；
- 未来启动跨平台时，按[安全评审流程](../治理/安全评审流程.md)为每个新增系统集成点建立记录，并更新白皮书适用范围与默认开启能力清单。
