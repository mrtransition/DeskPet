# 受限技能系统评估（P-13）

> 状态：✅ 已完成（结论：暂不引入技能运行时）
> 评估日期：2026-11-13
> 评估方式：维护者依据 v2.3.0 实现与治理基线自评
> 关联：[工具调用能力边界](../治理/工具调用能力边界.md)、[安全评审流程](../治理/安全评审流程.md)、[隐私与安全白皮书](../治理/隐私与安全白皮书.md)
> 决策有效期：至下一次重评触发条件出现

## 1. 结论摘要

**当前不引入任何形式的“技能运行时”或通用插件系统。**

DeskPet 已有的扩展面（人格 JSON、皮肤包、八态图集、社区画廊）全部是**数据扩展**，不包含可执行代码，也不改变主进程能力集合。未来若确有必要引入“受限技能”，只接受**声明式、无代码、动作映射到编译期白名单**的形态，并须先完成独立安全评审（新增 `INT-xxx` 记录）。

明确拒绝：通用插件系统、脚本沙箱（Lua / JS / Python）、原生动态库、下载即执行的技能包、技能自带网络请求或凭据访问。

## 2. 现状盘点

| 扩展点 | 形态 | 是否可执行代码 | 能力变化 | 现有防线 |
|---|---|---|---|---|
| 人格 | JSON（名称 / 提示词 / 开场白 / 动画 / 记忆标签） | 否 | 仅影响提示词与前端表现 | 导入时字段校验与同名冲突提示；不接触工具定义 |
| 皮肤包 | `.deskpet-skin.zip`（图片 / 音频 / `skin.json` 状态映射） | 否 | 仅影响渲染资源 | 条目数 / 体积 / 解压上限、文件名 basename 化、路径穿越拒绝、缺失状态回退 `idle` |
| 八态单图 | PNG / GIF / WebP | 否 | 仅影响渲染资源 | 4×2 切割、留白裁剪、画布统一 |
| Codex 宠物包 | 图集 + `pet.json` | 否 | 仅影响渲染资源 | 导入入口已屏蔽，历史条目只读切换 / 删除 |
| 社区画廊 | 静态 `docs/gallery/` | 否 | 无（仓库内展示） | 无应用内网络请求、无自动安装 |
| 工具调用 | 编译期固定 6 个工具 | 是（主进程实现） | 由代码决定，技能无法扩展 | 编译期白名单、逐项授权、参数二次校验、失败关闭、可撤销、审计 |

关键事实：

- 工具集合写死在 `tool_defs_raw()`，不读取外部工具清单，模型不能自定义工具；
- 主进程没有技能目录扫描、动态库加载或脚本引擎；
- 渲染层 CSP 为 `script-src 'self'`，禁止内联脚本、远程脚本、`eval` 类动态执行与 `frame`；
- 皮肤包与人格导入只解析数据，不执行其中的任何字段；
- 现有“扩展”不会让模型获得新能力，只会改变外观、语气与记忆偏好。

因此当前不存在“技能系统”这一攻击面，P-13 的评估对象是**未来是否要打开它**。

## 3. 候选方案对比

| 方案 | 描述 | 安全边界 | 维护成本 | 与轻量定位 | 结论 |
|---|---|---|---|---|---|
| A. 不引入技能运行时 | 保持数据扩展 + 编译期工具 | 攻击面最小；新增能力必须改代码并评审 | 低 | 一致 | ✅ **推荐（当前采用）** |
| B. 声明式受限技能 | `skill.json` 声明名称、说明、允许的动作与参数域；动作只能引用已有工具或固定 UI 动作 | 中；需清单校验、逐技能授权、默认关闭、可撤销、审计 | 中 | 基本一致 | 🟡 仅作为未来唯一可接受形态 |
| C. 沙箱脚本技能 | WASM / Lua / JS 沙箱内运行第三方逻辑 | 高；沙箱逃逸、资源耗尽、隐式出站难以完全收敛 | 高 | 冲突 | ❌ 暂不引入 |
| D. 通用插件系统 | Node / Python / 原生进程，插件自带依赖与网络 | 极高；等价于把机器与数据交给第三方代码 | 极高 | 严重冲突 | ❌ 明确拒绝 |

## 4. 若未来引入方案 B 的安全边界

以下条件缺一不可，且须先新增安全评审记录并登记到[安全评审登记表](../治理/安全评审/README.md)：

### 4.1 形态约束

- 技能包**只含声明与静态资源**，不含脚本、二进制、动态库或安装钩子；
- 技能不能注册新工具，只能引用已存在的编译期动作（如 `create_reminder`、`open_url`）；
- 技能不能修改系统提示词的全局部分，只能提供受限的“场景片段”，且与用户人格冲突时以用户配置优先；
- 技能不能读取会话正文、记忆正文、密钥、剪贴板或文件系统；
- 技能不能发起网络请求；需要出站时必须复用已有工具及其域名白名单。

### 4.2 安装与来源

- 仅支持本地手动导入，不提供“一键安装”或应用内技能市场；
- 导入前展示名称、作者、版本、将使用的动作与参数域、许可证；
- 同名技能默认不覆盖，由用户显式选择；
- 技能包需附带内容哈希；未来若引入签名，验签失败一律拒绝；
- 不自动更新技能，更新等同一次新的导入与授权。

### 4.3 授权与撤销

- 每个技能独立开关，**默认关闭**；
- 首次启用时逐项确认其引用的动作；高危动作不得提供“始终允许”；
- 技能开关与动作授权可在设置页查看、逐项撤销、一键全部撤销；
- 撤销立即生效，不保留后台行为；
- 技能停用后其提供的提示片段与快捷动作同时失效。

### 4.4 运行与审计

- 解析失败、字段缺失、动作不在白名单、参数越界：一律拒绝加载（fail closed）；
- 技能包体积、条目数、文本长度设上限；
- 审计记录只写技能 ID、动作名、结果与时间，不写参数正文与对话内容；
- 提供“安全模式”：跳过全部技能加载，仅保留核心聊天。

## 5. 明确拒绝的形态

| 形态 | 拒绝原因 |
|---|---|
| 技能内嵌 JS / Lua / Python / Shell | 需要脚本引擎与沙箱，逃逸与资源耗尽风险不可控 |
| 原生 DLL / 动态库 / 子进程 | 等价于任意代码执行，无法用白名单收敛 |
| 技能自带 HTTP 客户端或自定义域名 | 成为数据外带通道，破坏出站域名披露承诺 |
| 技能读取凭据管理器 / 环境变量 / 浏览器数据 | 直接违反密钥隔离与隐私承诺 |
| 应用内技能市场、评分、自动安装 | 引入账号、审核、分发与供应链责任，超出轻量定位 |
| 静默更新技能 | 用户无法感知能力变化，违背可感知授权原则 |

## 6. 重评触发条件

出现以下任一情况时重新评估，而不是按时间表自动推进：

1. 连续多个版本收到**可复现的用户需求**，且现有数据扩展（人格 / 皮肤 / 快捷动作）无法满足；
2. 现有工具集已稳定，且新增能力可以通过“声明式动作映射”表达，无需新代码；
3. 维护者具备评审第三方技能包的时间与流程；
4. 已完成方案 B 的原型、威胁建模与至少一次外部复核；
5. 治理基线（默认关闭、逐项授权、撤销、审计、发布说明）仍完整有效。

## 7. 风险与缓解

| 风险 | 表现 | 缓解 |
|---|---|---|
| 功能膨胀 | 技能数量增长，核心聊天被稀释 | 默认关闭、无市场、仅本地导入、按需启用 |
| 权限蔓延 | 技能逐步索取更多动作 | 动作白名单 + 逐项授权 + 高危动作禁止记忆 |
| 供应链攻击 | 技能包被替换或植入代码 | 只允许声明式内容、哈希校验、未来签名、无自动更新 |
| 隐式出站 | 技能绕过工具直接联网 | 技能无网络能力；出站只走已有工具与域名白名单 |
| 维护负担 | 兼容性与审核成本上升 | 技能格式版本化；不兼容直接拒绝加载并保留旧版 |

## 8. 验收与后续

- 本报告明确了“是否引入”（暂不引入）与“安全边界”（仅方案 B，且满足第 4 节）；
- 当前无需新增代码、工具或系统集成点，因此不新增 `INT-xxx` 记录；
- 若未来启动方案 B，必须先完成：需求准入检查 → 安全评审记录 → 原型与威胁建模 → 默认关闭实现 → 回归测试；
- 在方案 B 落地前，任何“技能 / 插件”相关 PR 均按本报告拒绝。
