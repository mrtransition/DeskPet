# 需求准入检查清单

> 工作包：P-01 功能开关默认值纪律制度化
> 版本：v1.0（2026-11-13）
> 适用：所有新增功能、能力扩展、系统集成点、新依赖与默认值调整
> 关联：[默认开启能力清单](默认开启能力清单.md)、[安全评审流程](安全评审流程.md)、[PR 模板](../../.github/PULL_REQUEST_TEMPLATE.md)

## 1. 目的

在需求进入开发前回答六个问题，防止“技术可行”替代“产品相关”，防止新功能默认开启后不断稀释核心体验。

本清单不是形式审查：**任一问题回答不明确，应暂缓进入开发，或降级为评估事项**。

## 2. 使用方式

1. **Issue 阶段**：功能建议使用 `.github/ISSUE_TEMPLATE/feature_request.yml`，其中包含本清单六问；维护者据此给出准入结论。
2. **PR 阶段**：PR 描述必须包含本清单结论与证据链接；未填写的不进入代码审查。
3. **发布阶段**：准入结论与默认值变化同步写入发布说明。
4. **复审**：需求范围发生变化时重新判定，不以首次结论覆盖后续扩展。

## 3. 六个必答问题

### Q1. 是否直接服务于“轻量桌面 AI 聊天宠物”的核心目的？

| 判定 | 标准 |
|---|---|
| 通过 | 能说明它如何让“点击即聊”更快、更稳、更可信或更有陪伴感；受益路径不超过两步 |
| 条件通过 | 只服务于特定人群或特定场景，但可默认关闭且不打扰主链路 |
| 不通过 | 主要价值是“功能更多”“看起来更强”，与聊天宠物无直接关系 |

**需附证据**：一句话价值主张 + 用户操作路径 + 与现有能力的差异。

### Q2. 是否默认关闭或归入实验性增强？

| 判定 | 标准 |
|---|---|
| 通过 | 默认关闭，或归入“实验性增强”折叠区，首次使用有清晰说明 |
| 条件通过 | 属于核心链路的一环，默认开启但可一键关闭，并已登记到《默认开启能力清单》 |
| 不通过 | 偏离核心链路却默认开启，或无法关闭 |

**需附证据**：默认值、设置项位置、关闭后的行为、是否登记到默认开启清单。

### Q3. 是否扩大攻击面？如扩大，是否经过安全评审？

| 判定 | 标准 |
|---|---|
| 通过 | 不新增系统权限、不出站、不读取敏感数据；或已存在对应 `INT-xxx` 评审记录且结论为通过 |
| 条件通过 | 新增能力但已设计最小权限、逐次授权、白名单与失败关闭，评审结论为“条件通过”并列出前置条件 |
| 不通过 | 新增文件系统读写、命令执行、任意网络访问等高危能力，且没有多层防线 |

**需附证据**：数据流向、权限范围、授权方式、撤销方式、评审记录编号。

### Q4. 是否可被用户随时撤销或关闭？

| 判定 | 标准 |
|---|---|
| 通过 | 有明确开关或授权项；撤销后立即生效；不需要重装或改配置文件 |
| 条件通过 | 撤销需要重启，但设置页有明确提示 |
| 不通过 | 开启后无法关闭，或关闭后仍保留后台行为 |

**需附证据**：开关路径、生效时机、撤销后的数据与进程行为。

### Q5. 是否显著增加主程序体积、依赖复杂度或维护成本？

| 判定 | 标准 |
|---|---|
| 通过 | 无新增运行时依赖，或新增依赖可离线构建、体积与维护成本可接受 |
| 条件通过 | 新增依赖或明显代码量，但有明确收益、可替换方案评估与退出策略 |
| 不通过 | 引入重型运行时（3D / 物理引擎 / 通用插件系统 / 大模型本地运行时）却没有阶段性评估 |

**需附证据**：依赖清单、包体变化、替代方案、后续维护责任。

### Q6. 是否与现有功能产生协同，而非单纯堆叠？

| 判定 | 标准 |
|---|---|
| 通过 | 复用现有数据、人格、皮肤、提醒或工具链路，减少用户重复配置 |
| 条件通过 | 独立功能，但与核心链路有清晰衔接点 |
| 不通过 | 与现有功能重叠、入口分散、用户需要理解两套概念 |

**需附证据**：复用点、与现有功能的边界、是否合并入口。

## 4. 附加门禁

以下任一条命中时，必须完成对应动作后才能合并：

| 门禁 | 触发条件 | 必须动作 |
|---|---|---|
| 安全评审 | 新增工具、感知源、系统集成点、外部输入解析、新出站域名 | 新增 `docs/治理/安全评审/INT-xxx-*.md`，结论为通过或条件通过 |
| 默认开启登记 | 新能力默认开启 | 更新《默认开启能力清单》，写明理由与关闭路径 |
| 收敛说明 | 移除、合并、降级或改变默认值 | 发布说明写入“收敛与移除”及原因 |
| 隐私白皮书同步 | 数据流、密钥、日志、出站域名变化 | 更新《隐私与安全白皮书》并提升文档版本 |
| 回归测试 | 新增行为或安全边界 | 至少一项自动化测试或可复现的手工验收步骤 |
| 文档同步 | 用户可见行为变化 | README / 设置页文案 / ROADMAP 至少一处同步 |

## 5. 准入结论

| 结论 | 含义 | 后续动作 |
|---|---|---|
| ✅ 通过 | 六问均有明确答案，无附加门禁 | 进入开发，PR 引用本结论 |
| 🟡 条件通过 | 有明确前置条件（默认关闭、评审整改、范围缩减） | 条件未完成前不合并 |
| ⏸ 暂缓 | 关键问题回答不明确，或收益/成本不成立 | 降级为评估事项，记录待补信息 |
| ❌ 拒绝 | 偏离核心、无法撤销、或高危能力无防线 | 关闭需求并说明原因 |

## 6. PR 中的记录格式

```markdown
## 需求准入

- 结论：✅ 通过 / 🟡 条件通过 / ⏸ 暂缓 / ❌ 拒绝
- Q1 核心相关性：
- Q2 默认值：默认关闭 / 默认开启（已登记）
- Q3 攻击面：无变化 / 已评审（INT-xxx）
- Q4 可撤销性：
- Q5 体积与依赖：
- Q6 协同关系：
- 收敛说明：无 / 见发布说明
```

## 7. 判定示例

| 需求 | 结论 | 理由 |
|---|---|---|
| 新增“对话中一键复制代码块” | ✅ 通过 | 核心聊天链路的直接增强，无新权限，默认可用 |
| 新增“剪贴板自动总结” | 🟡 条件通过 | 读取剪贴板属敏感能力：默认关闭、逐次授权、仅本地提示、可撤销；需 `INT` 记录 |
| 新增“任意文件读取工具” | ❌ 拒绝 | 与核心目的无直接关系，高危能力且无法用白名单收敛 |
| 新增“桌面 3D 宠物渲染” | ⏸ 暂缓 | 与轻量定位冲突，需先形成体积与性能评估报告 |
| 移除“费用估算”界面 | ✅ 通过（收敛） | 降低维护成本与非核心干扰；发布说明必须写明移除原因 |

## 8. 维护指标

- 默认开启能力数量不因版本迭代显著增加；
- 每个新增工具 / 感知源 / 系统集成点都有对应 `INT-xxx` 记录；
- 每次发布说明都包含收敛或移除章节；
- 被暂缓的需求保留待补信息，避免反复讨论同一问题。
