# DeskPet 隐私与安全白皮书（初版）

> 工作包：P-03 隐私与安全白皮书初版
> 文档版本：v1.0
> 编制日期：2026-11-13
> 对应产品版本：DeskPet v2.3.0
> 适用范围：Windows 桌面版（Tauri v2）
> 文档状态：公开可查阅；随安全设计变更同步更新，变更记录见文末

## 1. 摘要

DeskPet 是运行在用户桌面上的本地 AI 聊天宠物。它的隐私设计可以用四句话概括：

1. **数据留在本机**：会话、记忆、提醒、人格、皮肤与设置都保存在 `%APPDATA%\com.mrtransition.deskpet\`，不经过 DeskPet 的中转服务器；
2. **密钥不在应用数据里**：API Key 只写入 Windows 凭据管理器，不进入 `data.json`、日志、导出文件或渲染层（WebView）；
3. **没有遥测**：不收集使用统计、崩溃信息、设备标识，也不做后台出站；出站只发生在用户主动对话、使用天气 / 联网搜索或检查更新时；
4. **能力可撤销**：工具调用逐项授权，设置页可随时改回“每次询问”或“始终拒绝”，关闭工具总开关后模型看不到任何工具。

本白皮书说明这些承诺的**具体实现、可验证入口与已知限制**。它不是法律意义上的隐私政策，而是面向用户与贡献者的技术透明度文档。

## 2. 威胁模型与承诺边界

### 2.1 防护目标

| 目标 | 说明 |
|---|---|
| 密钥不泄露到磁盘与界面 | 即使有人拿到 `data.json`、日志或导出的配置，也无法还原 API Key |
| 对话内容不被静默外传 | 除用户配置的模型服务外，不向任何第三方发送对话正文 |
| 工具调用不越权 | 模型不能执行未定义的工具，不能绕过白名单打开任意链接或应用 |
| 本地数据可审查 | 数据文件是可读 JSON，用户可自行检查、备份、删除 |
| 失败不扩大影响 | 授权超时、网络失败、解析失败一律按“不执行 / 不发送”处理 |

### 2.2 不在防护范围内

以下场景需要用户自行负责，DeskPet 无法提供端到端保证：

- **模型服务商侧的数据处理**：对话内容会发送给用户选择的模型服务（OpenAI、DeepSeek、Ollama 等），其留存、训练与合规策略由该服务商决定；
- **本机已被攻破**：拥有当前用户权限的恶意软件可以读取 `%APPDATA%`、注入进程或读取凭据管理器；DeskPet 不提供对抗本机管理员的保护；
- **用户主动导出与分享**：导出的会话 Markdown、配置 JSON、皮肤包、诊断日志由用户自行保管；
- **未做代码签名的分发包**：当前发布产物未做 Authenticode 签名，Windows SmartScreen 可能提示；用户应核对下载来源；
- **更新包完整性**：更新链路目前仅强制 HTTPS，尚未实现签名 / 哈希校验（见第 9 节）。

## 3. 本地数据地图

默认数据目录：`%APPDATA%\com.mrtransition.deskpet\`（由 Tauri `identifier` 决定）。

| 文件 / 目录 | 内容 | 敏感级别 | 生命周期 |
|---|---|---|---|
| `data.json` | 供应商配置（不含 Key）、人格、会话与消息、长期记忆、提醒、设置、统计计数 | 高（含对话与记忆） | 持续写入；原子替换；保留上一份备份 |
| `data.json.bak` | 上一次 `data.json` 的副本 | 高 | 主文件损坏时回退；约每 5 分钟或主文件较小时刷新 |
| `data.json.corrupt-<时间戳>` | 解析失败时保留的损坏现场 | 高 | 保留供排查，不自动上传 |
| `skins/<id>.json` | 导入皮肤的图片 / 音效（按引用存取） | 中 | 随皮肤删除或未引用时清理 |
| `skins/current.json` | 当前生效皮肤的资源快照 | 中 | 随皮肤切换更新 |
| `exports/` | 用户主动导出的会话 Markdown、配置 JSON、皮肤包、更新包 | 高 | 由用户自行管理 |
| `deskpet.log` | JSON Lines 结构化日志（脱敏） | 中 | 超过 200,000 字节时删除重建 |
| `deskpet.log.legacy-<时间戳>` | 旧版纯文本日志归档 | 中 | 保留供排查，不自动上传 |

**数据流原则：**

- 渲染层通过 Tauri IPC 请求主进程读写数据；密钥读写命令不返回密钥内容到渲染层；
- 皮肤资源在保存前从 `data.json` 摘出到 `skins/*.json`，避免每次保存都搬运十几 MB；
- 没有云端账户体系，也没有跨设备同步。

## 4. 密钥生命周期

### 4.1 存储位置

- 使用 Rust `keyring` crate，服务名固定为 `DeskPet`，账户名为供应商 ID（如 `p-deepseek`）；
- Windows 上落到 **Windows 凭据管理器**（Credential Manager），受当前 Windows 用户账户保护；
- `data.json` 中供应商对象的 `apiKey` 字段在迁移后会被删除；新版本不再写入明文密钥。

### 4.2 生命周期

| 阶段 | 行为 |
|---|---|
| 创建 / 更新 | 用户在设置页或首次引导中输入 Key → 前端调用 `key_set` → 主进程写入凭据管理器；空字符串等同删除 |
| 读取 | 仅主进程在发起模型请求时通过 `key_get` 读取，用于构造 `Authorization` 头；渲染层无法读取 |
| 使用 | 只在请求用户配置的模型端点时使用；不写入日志、不写入导出配置、不进入工具参数 |
| 迁移 | 启动时 `migrate_legacy_secrets()` 扫描旧版 `data.json` 中的明文 `apiKey`，迁移到凭据管理器后立即从业务库删除 |
| 删除 | 删除供应商或「重置全部数据」时调用 `key_del()` 删除对应凭据；重置会遍历所有供应商逐一删除 |
| 导出 | 配置导出在前端将 `apiKey` 置空；日志脱敏会遮盖 `sk-`、`Bearer`、`api_key=` 等模式 |
| 备份 | 密钥不在 `data.json` 中，因此 `data.json.bak` 与损坏现场也不含密钥 |

### 4.3 已知限制

- 凭据管理器中的条目在卸载 DeskPet 后可能仍保留（当前为便携分发，无安装器 / 卸载器）；用户可在 Windows「凭据管理器 → Windows 凭据」中手动删除 `DeskPet` 条目；
- 如果用户曾运行 v2.0 及更早版本并在 `data.json` 中留下明文 Key，迁移会在下次启动时执行；迁移前该文件仍可能包含明文，建议升级后检查并删除旧备份。

## 5. 工具调用与授权

工具能力边界、禁止清单与多层防线要求见[《工具调用能力边界》](工具调用能力边界.md)。本节只说明隐私相关行为。

### 5.1 授权方式

- 每个工具独立保存授权状态：`ask`（每次询问，默认）/ `allow`（始终允许）/ `deny`（始终拒绝）；
- 首次调用弹出授权卡片，展示工具名、参数预览、能力说明与“仅本地 / 会出站”标识；
- 授权等待 120 秒，超时按拒绝处理；
- 只有用户显式选择“始终允许 / 始终拒绝”才记忆；关闭卡片不影响后续询问；
- 设置 → 隐私 → 工具能力与授权可逐项修改，修改立即生效，无需重启；
- 工具总开关关闭后，不向模型暴露任何工具定义。

### 5.2 敏感数据流

| 工具 | 读取什么 | 发送到哪里 | 是否落盘 |
|---|---|---|---|
| `create_reminder` | 模型给出的提醒内容与时间 | 仅本地 `reminders` | 是（提醒内容） |
| `read_clipboard` | 当前剪贴板纯文本（≤8000 字符） | 作为工具结果回传给模型服务 | 否（日志不记录） |
| `open_url` | 模型给出的 URL | 系统默认浏览器；域名须在白名单 | 否 |
| `open_app` | 模型给出的应用名 | 本地固定白名单应用 | 否 |
| `get_weather` | 城市名 | Open-Meteo | 否 |
| `web_search` | 搜索关键词 | DuckDuckGo | 否 |

### 5.3 剪贴板感知（默认关闭）

- 开启后由主进程定时读取剪贴板纯文本，最多保留 2000 字符用于比对变化；
- 只向宠物发送 80 字符以内的预览提示，**不自动发送给模型、不写日志、不持久化**；
- 用户点击提示后才进入正常聊天流程；
- 可随时在设置中关闭；关闭后不再读取。

## 6. 出站请求与域名清单

DeskPet 没有中转服务器。所有出站请求都由主进程（Rust / reqwest）直接发往以下目的地：

| 场景 | 域名 | 触发条件 | 发送内容 | 默认状态 |
|---|---|---|---|---|
| 模型对话 | 用户配置的模型服务域名（如 `api.openai.com`、`api.deepseek.com`、`localhost:11434`） | 用户发送消息 | 会话上下文、人格提示、必要参数 | 使用即发生 |
| 天气查询 | `geocoding-api.open-meteo.com`、`api.open-meteo.com` | 模型调用 `get_weather` 且用户放行 | 城市名 / 经纬度 | 默认拒绝 |
| 联网搜索 | `html.duckduckgo.com` | 模型调用 `web_search` 且用户放行 | 搜索关键词 | 默认拒绝 |
| 更新检查 | `api.github.com`（默认）或用户填写的清单地址 | 用户手动检查，或显式开启“启动时自动检查” | 常规 HTTPS 请求，无设备标识 | 自动检查默认关闭 |
| 更新下载 | 清单中提供的 HTTPS 地址 | 用户确认下载 | 无额外内容 | 用户主动触发 |
| 打开链接 | 用户默认浏览器访问的网站 | 模型调用 `open_url` 且用户授权、域名在白名单 | 浏览器正常请求 | 逐次询问 |

**不会发生的出站：**

- 启动、关闭、切换皮肤 / 人格、写日志、统计、崩溃上报；
- 剪贴板感知、健康提醒、TTS 朗读（使用系统语音，零联网）；
- 后台轮询模型服务或更新源（自动更新默认关闭）。

## 7. 日志与可观测性

- 日志格式：JSON Lines，每行包含 `ts` / `level` / `event` / `msg`；
- 写入位置：应用数据目录下的 `deskpet.log`；
- 体积控制：超过 200,000 字节时删除重建（不是完整轮转，见已知限制）；
- 脱敏：写入前调用 `redact_secrets()`，遮盖 `sk-` 令牌、`Bearer` 令牌、`api_key=` / `apikey=` / `api-key=` 值与 `Authorization:` 头；
- 不记录：API Key、请求头、请求体、对话正文、剪贴板内容；
- 会记录：出站域名、协议类型、模型名、HTTP 状态、是否成功、延迟、重试次数；启动 / 退出 / 数据迁移 / 皮肤资源外置 / 更新下载等事件；
- 没有远程日志收集，也没有“发送诊断”按钮；日志是否分享完全由用户决定。

## 8. 渲染层与本地接口安全

- 四个窗口（`pet`、`bubble`、`settings`、`guide`）启用统一 CSP：默认仅允许本地资源与 IPC，禁止内联脚本、插件、内嵌框架、Worker；
- `capabilities/default.json` 只授予窗口操作与事件所需的最小权限，不开放文件系统、Shell、HTTP 等插件权限；
- 前端无 npm 依赖、无构建链，资源随 exe 内嵌，减少供应链风险；
- Markdown 渲染对链接协议做白名单处理，代码块转义，外链图片不自动加载；
- 皮肤包导入有大小、条目数与路径穿越 / 压缩炸弹防护；SVG 资源拒绝脚本、外链图片与事件属性；
- 外部链接只通过系统默认浏览器打开，不在应用内加载网页。

## 9. 已知限制与待补事项

| 限制 | 影响 | 计划 |
|---|---|---|
| 更新包未做签名 / 哈希校验 | 只能保证 HTTPS 传输，无法识别被篡改的发布产物 | NFR-SEC-004，待补 |
| 日志不是完整轮转 | 超过 200KB 直接删除，无法保留历史；极端情况下丢失排查线索 | NFR-MNT-003，待补 |
| 无自动数据清理策略 | 会话 / 记忆 / 日志会持续增长，需用户手动清理 | DR-002，待补 |
| 无细粒度授权撤销面板 | 当前按工具撤销；没有按次、按会话、按时间段的授权视图 | P-08，中期 |
| 卸载不询问是否保留数据 | 便携分发没有卸载器；用户需手动删除 `%APPDATA%` 目录与凭据 | FR-SYS-010，待补 |
| 旧版明文 Key 迁移前的窗口期 | 升级前旧 `data.json` 可能含明文 Key | 升级后检查并删除旧备份 |
| 模型服务商侧数据处理不可控 | 对话内容一旦发出，DeskPet 无法撤回 | 用户选择可信服务商；本地 Ollama 可完全闭环 |

## 10. 漏洞披露与安全反馈

- 安全问题请**不要**先开公开 Issue；通过 GitHub 仓库的 Security Advisory（私密漏洞报告）或直接联系维护者；
- 报告请包含：受影响版本、复现步骤、影响范围、是否已在野利用；
- 维护者会在确认后给出修复计划，并在发布说明“安全与隐私变更”中披露必要时信息；
- 不提供漏洞赏金；对负责任披露会在发布说明中致谢（如报告者同意）。

## 11. 用户自查清单

| 想确认的事 | 怎么做 |
|---|---|
| 数据存在哪里 | 设置 → 隐私 → 本地数据；或直接打开 `%APPDATA%\com.mrtransition.deskpet\` |
| Key 是否在数据文件里 | 用文本编辑器搜索 `apiKey`；正常应为空字符串或不存在 |
| 应用是否联网 | 设置 → 隐私 → 出站域名披露；结合系统防火墙 / 资源监视器观察 |
| 哪些工具被允许 | 设置 → 隐私 → 工具能力与授权 |
| 如何彻底删除数据 | 设置 → 数据 → 重置全部数据；再手动删除数据目录与 Windows 凭据管理器中的 `DeskPet` 条目 |
| 日志里有什么 | 打开 `deskpet.log`，确认只有域名、状态与事件，没有对话正文与 Key |
