# 工具调用能力边界

> 工作包：P-02 工具调用能力边界文档化
> 版本：v1.0（2026-11-13）
> 基线：DeskPet v2.3.0
> 代码位置：`src-tauri/src/main.rs`（`tool_defs_raw` / `request_tool_auth` / `execute_tool` / 白名单函数）
> 关联：[隐私与安全白皮书](隐私与安全白皮书.md)、[安全评审流程](安全评审流程.md)

## 1. 边界原则

DeskPet 的定位是“轻量、私密、点击即聊的桌面 AI 聊天宠物”，不是通用桌面代理。工具调用的唯一合法性来自**辅助聊天**，因此遵循：

1. **编译期白名单**：模型能看到的工具集合固定写在代码中，不加载插件、不读取外部工具清单、不允许模型自定义工具；
2. **默认拒绝**：所有有副作用的工具首次调用必须经用户授权；出站工具默认拒绝；
3. **最小能力**：只提供完成聊天辅助所需的最小动作，参数在服务端（主进程）二次校验，不信任模型输出；
4. **失败关闭**：参数不合法、域名不在白名单、授权超时，一律拒绝执行并回传原因，不降级为“尽力执行”；
5. **可撤销**：用户可在设置页逐项改回“每次询问”或“始终拒绝”，无需重启；
6. **可审计**：工具执行结果回传模型前有明确摘要；本地日志只记录必要事件，不记录密钥与对话正文。

## 2. 当前工具清单

| 工具 | 能力类别 | 风险等级 | 默认授权 | 出站 | 撤销方式 |
|---|---|---|---|---|---|
| `create_reminder` | 本地写入（提醒列表） | 低 | 询问 | 否 | 设置 → 工具授权 |
| `read_clipboard` | 本地敏感读取 | 中 | 询问 | 结果回传模型 | 同上；或关闭工具总开关 |
| `open_url` | 本地系统动作 + 出站 | 中 | 询问 + 域名白名单 | 打开默认浏览器 | 同上；可删除白名单域名 |
| `open_app` | 本地进程启动 | 中 | 询问 + 固定应用白名单 | 否 | 同上 |
| `get_weather` | 出站查询 | 中 | **拒绝** | Open-Meteo | 显式改为询问 / 允许 |
| `web_search` | 出站查询 | 中 | **拒绝** | DuckDuckGo | 显式改为询问 / 允许 |

### 2.1 各工具的精确边界

#### `create_reminder`

- 仅写入本地 `reminders` 数组，不触发系统通知以外的行为；
- 内容截断到 60 字符；相对时间限制在 0.1 分钟 ~ 7 天；重复规则限定 `once / daily / weekly / interval`；
- 间隔限制 1 ~ 10080 分钟；
- 不接受任意脚本、命令或外部回调。

#### `read_clipboard`

- 只读取纯文本，不读取图片、文件列表或富文本格式；
- 最多返回 8000 字符（默认 2000），超出截断；
- 内容会作为工具结果回传给模型，授权卡片必须明确告知；
- 不写入日志，不自动持久化；
- 与「剪贴板感知」不同：后者只比对变化并在本地提示，不发送给模型。

#### `open_url`

- 仅允许 `http` / `https`；
- 域名必须命中 `toolSettings.openWhitelist`，匹配规则为“完全相等或以 `.域名` 结尾”，并忽略 `www.` 前缀；
- 只交给系统默认浏览器打开，不在应用内加载网页；
- 不接受 `file:`、`javascript:`、`data:` 等协议。

#### `open_app`

- 编译期固定五个目标：`notepad` / `calc` / `mspaint` / `explorer` / `snippingtool`；
- 只按固定可执行文件名启动，不拼接用户参数，不经过 shell；
- 不接受任意路径、任意命令行、环境变量或脚本。

#### `get_weather`

- 只向 `geocoding-api.open-meteo.com` 与 `api.open-meteo.com` 发送城市名 / 经纬度；
- 请求超时 12 秒；
- 不发送设备标识、会话内容或密钥；
- 默认拒绝，需用户显式放行。

#### `web_search`

- 只向 `html.duckduckgo.com` 发送搜索关键词；
- 最多解析 5 条结果；
- 使用固定 User-Agent，不附加设备指纹；
- 默认拒绝，需用户显式放行。

## 3. 明确禁止的能力

以下能力**不进入** DeskPet 工具集。即使技术上可行，也不作为“以后再说”的候选：

| 禁止项 | 原因 |
|---|---|
| 任意文件系统读取 / 写入 / 删除 / 重命名 | 与聊天宠物核心目的无直接关系，数据泄露与破坏风险高 |
| 任意命令 / Shell / PowerShell / 脚本执行 | 等价于把整台机器交给模型，无法用白名单收敛 |
| 注册表、服务、计划任务、驱动、系统策略修改 | 影响系统稳定性，撤销困难 |
| 进程枚举、注入、结束任意进程 | 可被用于绕过安全软件或破坏用户工作 |
| 读取浏览器 Cookie / 密码库 / 系统凭据 | 直接违反密钥隔离承诺 |
| 屏幕截图、摄像头、麦克风、键鼠记录（未经逐次授权） | 敏感感知能力，需独立评审与默认关闭；当前未启用 |
| 任意网络请求 / 自定义代理 / 任意请求头 | 会成为数据外带通道；当前仅保留固定出站域名 |
| 下载并执行插件、脚本、模型或二进制 | 等于引入无限制插件系统，违背短期路线 |
| 静默安装更新 / 自我提权 / 关闭安全软件 | 破坏用户对更新链路的控制 |
| 读取其他应用窗口内容 / 无障碍树遍历 | 攻击面过大，且与核心体验无直接关系 |
| 持久化后台驻留（除托盘与提醒调度器） | 不可见行为违背“轻量、可解释” |

**说明**：未来如确需引入文件或命令类能力，必须先完成独立的安全评审，并同时具备命令黑名单、沙箱化工作区、人机协同确认、逐次授权与审计记录等多层防线；在完成前不得以实验性功能形式提供。

关于“受限技能 / 插件系统”的评估结论见[受限技能系统评估](../评估/受限技能系统评估.md)：当前不引入任何技能运行时；未来仅接受声明式、无代码、动作映射到编译期白名单的形态。

## 4. 高危能力多层防线要求

本文件将“高危能力”定义为：可读写用户文件、可执行任意代码、可访问凭据、可持续采集敏感数据、可任意出站的能力。当前工具集不包含高危能力；`read_clipboard`、`open_url`、`open_app` 与出站查询按“中风险”管理。

若未来评审通过某项高危能力，至少需要以下防线，缺一不可：

| 层级 | 要求 |
|---|---|
| 1. 能力白名单 | 编译期固定工具与参数域，不接受模型自定义；高危动作默认不存在 |
| 2. 参数校验 | 主进程二次解析与规范化；路径必须落在沙箱目录；URL 必须协议 + 域名双白名单；拒绝符号链接与路径穿越 |
| 3. 人机协同 | 每次执行前展示目标、范围与影响；高危动作不得提供“始终允许” |
| 4. 最小权限 | 只申请完成动作所需的最小系统权限；不使用管理员权限；不读取无关文件 |
| 5. 隔离 | 独立工作目录、超时、输出大小上限、失败关闭；必要时使用受限子进程 |
| 6. 审计 | 记录动作类型、目标摘要、结果与时间；不记录密钥与正文；用户可查看与清除 |
| 7. 撤销 | 一键关闭能力；撤销立即生效；清除相关缓存与授权 |
| 8. 测试 | 至少覆盖越权路径、参数注入、路径穿越、超时与失败降级 |

## 5. 工具授权模型

状态机（按工具名独立保存于 `settings.toolSettings.auth`）：

```text
未设置 ──首次调用──> 询问 ──用户允许──> 执行
                     │        └─始终允许──> allow（后续直接执行）
                     ├─用户拒绝──> 不执行
                     └─始终拒绝──> deny（后续直接拒绝并提示）

设置页可随时把 allow / deny 改回 ask，或关闭工具总开关。
```

- 授权等待上限 120 秒，超时按拒绝处理；
- 授权按工具名隔离，并发调用不会互相覆盖；
- 工具总开关关闭时，不向模型暴露任何工具定义；
- 授权卡片展示工具名、参数预览、能力说明与“仅本地 / 会出站”标识；
- 授权结果与执行结果以简短摘要回传模型，最多 4 轮工具循环，避免无限自调用。

## 6. 新增工具的准入流程

1. 在《需求准入检查清单》中回答六问，说明为何必须新增工具而不是改进现有工具；
2. 提交 `docs/治理/安全评审/INT-xxx-*.md`，至少覆盖：数据流向、权限范围、授权方式、撤销能力、日志与审计、失败降级、风险评级、多层防线；
3. 默认关闭或默认询问；有出站或敏感读取的默认拒绝；
4. 在主进程实现参数白名单与失败关闭，并补充回归测试；
5. 更新本文件第 2 节、[默认开启能力清单](默认开启能力清单.md)与《隐私与安全白皮书》出站域名表；
6. PR 引用评审记录编号；没有记录不合并。

## 7. 移除与降级

工具能力只减不增是默认方向。出现以下情况时优先移除或降级：

- 连续两个版本无用户使用证据；
- 维护成本高于收益；
- 出现无法用白名单收敛的绕过路径；
- 与核心聊天链路的关联需要额外解释才能成立。

移除时同步删除工具定义、授权状态与文档条目，并在发布说明“收敛与移除”中写明原因。
