# 更新包校验与签名（NFR-SEC-004）

> 状态：v2.3.3 落地
> 关联需求：NFR-SEC-004、FR-SYS-004、FR-SYS-009、AC-018
> 关联决策：TBD-04（更新签名方案）——选择 **Ed25519**
> 维护责任：发布负责人

## 1. 结论

DeskPet 的更新下载不再只依赖 HTTPS。每个安装包在保存到本地之前必须同时通过：

1. **SHA-256 完整性校验**：清单中的 `sha256` 与下载字节的 SHA-256 完全一致；
2. **Ed25519 发布签名校验**：使用编译期内置的公钥验证签名，签名对象为 SHA-256 的小写 hex 字符串（UTF-8 字节）。

任意一项缺失或失败，主进程都会拒绝保存安装包，并写入 `update.verify_failed` 诊断日志（只含哈希前 12 位与失败原因，不含正文）。当前版本继续可用，不阻断启动。

应用仍然坚持「只下载、不静默安装」：校验通过后只把安装包保存到 `updates/`，由用户手动运行。

## 2. 清单格式

### 2.1 自定义最小清单

```json
{
  "version": "2.3.3",
  "notes": "更新说明",
  "url": "https://example.com/DeskPet-v2.3.3-win-x64.zip",
  "sha256": "64 位小写十六进制",
  "signature": "Ed25519 签名 base64（88 字符）"
}
```

`sha256` 也接受 `sha256:<hex>` 前缀与反引号；格式不合法会直接报错，不会静默降级为「无校验」。

### 2.2 GitHub Releases（默认更新源）

GitHub API 的 `assets[]` 中，优先读取安装包 asset 的 `digest`（形如 `sha256:<hex>`）。签名与哈希也可以写在 Release 正文末尾，更新检查会解析以下机器可读行（大小写、前置 `-` / `*` / `>` 与反引号均可容忍）：

```text
SHA256: <64 位小写 hex>
Ed25519-Signature: <base64>
```

> 正文行会随 `body` 一起返回，不需要额外网络请求；这也是当前发布流程采用的格式。

## 3. 密钥管理

### 3.1 生成

```powershell
node scripts/update-keygen.mjs
```

- 私钥默认写入 `.temp/deskpet-update-signing-key.pem`，`.temp/` 已被 `.gitignore` 忽略；
- 公钥（32 字节 raw key 的 base64）与指纹写入同目录 `.pub` 文件；
- **私钥必须离线备份，禁止提交到仓库、CI 日志或发布产物**；丢失私钥将无法为后续版本签名，只能轮换公钥并让旧客户端继续信任下一版本。

### 3.2 内置公钥

公钥常量位于 `src-tauri/src/main.rs`：

```rust
const UPDATE_ED25519_PUBKEYS: &[&str] = &["<base64>"];
```

数组支持多把公钥：签名只需被其中任意一把验证通过，用于平滑轮换。当前公钥指纹：

```text
d871a749e20fa144ea8e9cda9394a9d3343dd6d4e0c7ee77355138224c0471ee
```

### 3.3 轮换

1. 生成新密钥；
2. 先把新公钥加入数组（旧公钥保留），发布一个版本，让旧客户端同时信任新旧公钥；
3. 之后的新版本只用新私钥签名；
4. 至少保留一个完整发布周期后再移除旧公钥。

## 4. 发布流程

```powershell
# 1. 构建与打包（见 build.bat / README）
cargo build --release --target x86_64-pc-windows-gnu --manifest-path src-tauri/Cargo.toml

# 2. 计算哈希并签名（同时写出 .sha256 与 .sig）
node scripts/sign-update.mjs dist/DeskPet-v2.3.3-win-x64.zip

# 3. 把输出中的两行原样追加到 GitHub Release 正文末尾
#    SHA256: ...
#    Ed25519-Signature: ...
```

发布检查：

- [ ] `docs/releases/vX.Y.Z.md` 的安全章节记录公钥指纹与校验方式；
- [ ] GitHub Release 正文与归档文件一致，包含 `SHA256:` 与 `Ed25519-Signature:` 两行；
- [ ] `.sha256` / `.sig` 与安装包一同上传，便于用户离线核对；
- [ ] 在没有完成上述步骤时，不得把版本宣传为「安全更新」。

## 5. 验证与回归

- `cargo test` 覆盖：清单哈希解析、正文行与 asset digest 回退、非法哈希拒绝、Ed25519 验签成功/篡改失败/错误公钥失败、内置公钥长度与已知签名自检；
- 失败路径：哈希或签名不匹配时 `update_download` 在写盘前返回错误，`updates/` 不产生文件；
- 当前版本仍可正常聊天、提醒与导出，不因更新失败进入异常状态。

## 6. 边界与未覆盖项

- 不提供 Authenticode / 代码签名，Windows SmartScreen 仍可能提示；
- 不防御本机已被攻破、私钥泄露或内置公钥被替换的构建；
- 不自动安装、不后台轮询、不静默下载；
- 签名只证明「该字节序列由持有发布私钥的人签署」，不证明运行环境安全。
