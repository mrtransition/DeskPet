## 1. 能力概述

模型经用户放行后，用城市名查询当前天气（Open-Meteo，无需 API Key），用于“今天杭州天气怎么样”等聊天场景。

## 2. 数据流向

| 问题 | 回答 |
|---|---|
| 读取数据 | 模型给出的城市名 |
| 是否离开本机 | 是 |
| 发送目的地 | `geocoding-api.open-meteo.com`、`api.open-meteo.com` |
| 是否进入模型上下文 | 是：天气摘要会回传模型 |
| 是否落盘 | 否 |
| 是否写日志 | 出站日志记录域名、状态、延迟，不记录城市名 |

## 3. 权限范围

- 仅访问两个固定 Open-Meteo 域名；
- 请求超时 12 秒；
- 不发送设备标识、会话内容、密钥或剪贴板；
- 城市名经过 URL 编码，不拼接其他参数。

## 4. 授权与撤销

| 项 | 内容 |
|---|---|
| 默认状态 | **拒绝**（`toolSettings.auth.get_weather = "deny"`） |
| 首次调用 | 默认直接拒绝并提示；用户需先在设置页改为“每次询问”或“始终允许” |
| 是否可记忆 | 是 |
| 撤销位置 | 设置 → 工具能力与授权 |
| 撤销生效 | 立即 |
| 关闭后行为 | 不再发起任何天气请求 |

## 5. 日志与审计

- 出站日志记录 `host`、状态码、延迟、是否成功；
- 不记录城市名、经纬度或响应正文；
- 用户可在设置页看到出站域名披露。

## 6. 失败降级

| 场景 | 行为 |
|---|---|
| 用户拒绝 / 超时 | 不请求 |
| 城市名为空 | 返回错误 |
| 地理编码无结果 | 返回“没有找到城市” |
| 网络失败 / 超时 | 返回错误，不重试其他服务 |
| 响应格式异常 | 返回错误，不猜测数据 |

## 7. 风险评级

- 等级：中
- 理由：会把用户关注的城市名发送给第三方；属于低频、低敏感出站；
- 滥用场景：通过大量城市查询做流量滥用或推断用户位置。缓解：默认拒绝、逐次授权、固定域名、超时。

## 8. 防线清单

## 9. 结论

🟡 条件通过：

1. 默认必须保持“拒绝”；
2. 不得加入定位权限、IP 定位或后台自动刷新；
3. 若更换天气服务，需重新评审域名与发送字段；
4. 若增加“未来天气 / 空气质量”，需评估请求频率与隐私影响。

## 10. 验证与复审

- 手工验收：默认状态下让模型查天气 → 应被拒绝；改为“每次询问” → 授权卡片标“会出站” → 返回天气；
- 检查日志只有域名与状态，没有城市名；
- 复审触发：更换服务、增加字段、增加自动刷新。
