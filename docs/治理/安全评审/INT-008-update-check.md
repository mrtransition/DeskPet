## 1. 能力概述

检查 GitHub Releases（默认）或用户自定义清单，比较版本号；有更新时提示说明与下载地址，由用户确认后下载到本地 `exports/`，**不静默安装、不自动运行**。

## 2. 数据流向

| 问题 | 回答 |
|---|---|
| 读取数据 | 版本号、更新说明、下载地址 |
| 是否离开本机 | 是 |
| 发送目的地 | `api.github.com`（默认）或用户填写的清单地址；下载地址由清单提供 |
| 是否进入模型上下文 | 否 |
| 是否落盘 | 是：用户确认下载且 SHA-256 + Ed25519 双校验通过后保存到 `updates/`；失败不写盘 |
| 是否写日志 | 是：`update.verified` / `update.downloaded` 记录字节数与哈希前 12 位；失败写 `update.verify_failed`；不记录 URL 参数与正文 |

## 3. 权限范围

- 仅 HTTPS（非 HTTPS 清单 / 下载地址不采信）；
- 默认清单：`https://api.github.com/repos/mrtransition/DeskPet/releases/latest`；
- 解析 GitHub Releases API（`tag_name` / `body` / `assets[]`）与自定义最小清单（`version` / `notes` / `url`）；
- 下载地址优先 `.zip`，其次 `.exe`；排除 API 自我引用 URL；
- 清单读取 `sha256` / `signature`；GitHub 读取 asset `digest` 与正文 `SHA256:` / `Ed25519-Signature:` 行；
- 下载字节必须同时匹配 SHA-256 且通过内置 Ed25519 公钥验签，任一缺失或失败拒绝保存；
- 不执行下载的文件，不修改系统，不写注册表。

## 4. 授权与撤销

| 项 | 内容 |
|---|---|
| 默认状态 | 自动检查 **关闭**；手动检查不受限 |
| 开启方式 | 设置 → 关于 → 启动时自动检查更新 |
| 是否可记忆 | 是（设置项） |
| 撤销位置 | 同一设置项 |
| 撤销生效 | 立即；下次启动不再请求 |
| 关闭后行为 | 无后台更新请求；手动检查仍可用 |

## 5. 日志与审计

- 记录 `update.verified` / `update.downloaded` 与字节数；失败记录 `update.verify_failed`；
- 诊断日志中的哈希只保留前 12 位，签名与正文不入日志；
- 出站日志记录主机、状态、延迟；
- 不记录完整下载 URL、不记录响应正文。

## 6. 失败降级

| 场景 | 行为 |
|---|---|
| 清单请求失败 | 提示检查失败，保留当前版本，不阻断启动 |
| 清单格式不识别 | 明确提示缺少 `version` 或 `tag_name` |
| 下载地址非 HTTPS | 不采信 |
| 下载失败 / 中断 | 提示失败，不保留半截文件作为可执行产物 |
| SHA-256 不匹配 | 拒绝保存，提示可能被篡改或下载不完整，当前版本继续可用 |
| Ed25519 签名缺失 / 不匹配 | 拒绝保存；不提供“忽略校验”入口 |
| 用户取消 | 不下载、不安装 |

## 7. 风险评级

- 等级：中
- 理由：更新链路仍是供应链攻击的高价值目标；v2.3.3 已加入 SHA-256 + Ed25519 双校验，但未做 Authenticode 代码签名；
- 滥用场景：篡改发布产物、DNS / 代理劫持、伪造自定义清单。缓解：HTTPS、双校验、内置公钥、只下载不执行、用户手动确认、来源可见。

## 9. 结论

✅ 通过（v2.3.3 复审）：

1. NFR-SEC-004 已完成：SHA-256 + Ed25519 双校验，失败在写盘前拒绝；
2. 仍**不得**开启静默下载或自动安装；只下载、用户手动运行；
3. 自定义清单地址必须由用户显式填写，不提供远程下发；
4. 私钥离线保管，公钥轮换需保留旧公钥至少一个发布周期；
5. 发布说明继续披露“无 Authenticode 代码签名”等未覆盖项。

## 10. 验证与复审

- 测试：`parse_manifest()` 覆盖 GitHub Releases 真实响应、自定义清单、非 HTTPS 地址、缺失字段；新增 SHA-256 / Ed25519 解析、非法哈希拒绝、验签成功 / 篡改失败 / 错误公钥失败、已知哈希向量与内置公钥自检；
- 手工验收：点击检查更新 → 显示版本比较结果；确认下载 → 双校验通过后文件出现在 `updates/` 且未自动运行；篡改哈希或签名 → 拒绝保存；
- 复审触发：改为自动安装、切换更新源、增加增量更新、轮换签名密钥。
