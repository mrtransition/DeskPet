## 1. 能力概述

用户在「关于 → 本地诊断包」点击按钮后，主进程生成一个 JSON 文件，包含版本、操作系统、数据目录、条目计数、白名单式设置快照、最近授权记录与日志尾部。用于让用户自行排障并**自主决定**是否分享，不自动上传、不自动附加到反馈。

## 2. 数据流向

| 问题 | 回答 |
|---|---|
| 读取数据 | 应用版本、OS / 架构、应用数据目录、条目计数、白名单设置项、最近 20 条授权记录、`deskpet.log` 最近 200 行 |
| 数据是否离开本机 | 否（除非用户自行分享文件） |
| 发送到哪里（域名 / 进程） | 仅写入 `<app_data>/exports/deskpet-diagnostics-*.json` |
| 是否进入模型上下文 | 否 |
| 是否落盘（文件 / 位置 / 保留时间） | 是，exports 目录；保留时间由用户管理 |
| 是否写入日志 | 是，仅记录「已生成诊断包 + 路径」，不记录包内容 |

## 3. 权限范围

- 需要的系统权限：应用数据目录读写（已有）；
- 是否可用更小权限完成：是，无需网络与提权；
- 是否涉及管理员权限 / 提权：否；
- 访问边界：只读取应用自身数据目录；不扫描用户目录、不读取其他应用数据。

## 4. 授权与撤销

| 项 | 内容 |
|---|---|
| 默认状态 | 不自动生成（用户主动点击） |
| 首次调用行为 | 用户点击「生成诊断包」后执行一次 |
| 是否可记忆 | 否，每次都需要用户操作 |
| 用户在哪里撤销 | 无需撤销；可删除 exports 下的文件 |
| 撤销是否立即生效 | 删除文件即生效 |
| 关闭后是否仍有后台行为 | 否 |

## 5. 日志与审计

- 记录的事件：`diagnostics.export`（info，含导出路径）；
- 是否包含敏感内容：导出包**不含**会话正文、记忆正文、提醒内容、密钥、皮肤资源；日志尾部经 `redact_secrets` 脱敏；
- 用户能否查看与清除：是，设置页提供「打开导出目录」；
- 脱敏方式：白名单字段 + 日志密钥脱敏。

## 6. 失败降级

| 场景 | 行为 |
|---|---|
| 用户取消 | 不生成文件 |
| exports 目录不可写 | 返回错误提示，不影响应用其他功能 |
| 日志文件缺失 | 诊断包仍生成，`logTail` 为空 |
| 序列化失败 | 返回错误，不留下半截文件（单次写入） |
| 用户误分享 | 包内明确标注 `contains` 字段，说明不含哪些内容 |

原则：失败关闭（fail closed），不降级为“自动上传日志”。

## 7. 风险评级

- 等级：中
- 理由：诊断包可能包含数据目录路径、设置偏好与授权记录，属于环境信息；虽然不含正文与密钥，但分享后仍可能暴露使用习惯；
- 主要滥用场景：用户误将诊断包公开发布。缓解：内容白名单、`contains` 声明、不自动上传、只在用户点击时生成；
- 现有缓解措施：不包含对话 / 记忆 / 提醒正文，不包含密钥，日志尾部脱敏。

## 9. 结论

🟡 条件通过：

1. 必须保持“用户主动点击才生成”，不得自动上传或自动附带到任何网络请求；
2. 不得把会话 / 记忆 / 提醒正文、密钥或皮肤资源加入诊断包；
3. 新增字段必须经过白名单评审，不能直接把整个 `data.json` 打包；
4. 导出目录与文件名必须继续走 `sanitize_export_filename` / 固定前缀。

- 检查 `deskpet.log` 只记录导出路径；
