# 默认开启能力清单

> 工作包：P-01 功能开关默认值纪律制度化
> 版本：v1.0（2026-11-13）
> 基线：DeskPet v2.3.0
> 数据来源：`src-tauri/src/main.rs` 中 `DEFAULT_STATE`、各能力读取默认值的兜底逻辑
> 维护规则：新增默认开启能力必须在本表登记；默认值变化必须同步发布说明

## 1. 为什么要单独维护这张表

“默认开启”是最容易被忽视的产品决策：每加一个默认开启项，用户就多一层打扰、攻击面就多一个入口、卸载理由就多一条。本表把当前默认值变成可审阅的基线，并为版本迭代提供两个问题的答案：

1. 这个版本是否让默认开启能力变多了？
2. 每一项默认开启能力，用户在哪里关闭？

## 2. 核心链路（默认开启，结构性能力）

| 能力 | 默认值 | 关闭 / 退出方式 | 理由 | 分类 |
|---|---|---|---|---|
| 桌面宠物窗口（透明置顶、不入任务栏） | 开启 | 退出应用 | 产品本体 | 核心 |
| 单击宠物弹出气泡、流式聊天 | 开启 | 不使用 / 退出 | “点击即聊”核心体验 | 核心 |
| 多供应商配置（含内置演示模式） | 开启（演示模式为默认供应商） | 切换到其他供应商 / 不配置 | 无 Key 可体验，降低上手门槛 | 核心 |
| 长期记忆写入与按相关度注入（≤5 条） | 开启 | 删除单条记忆 / 重置数据 | 仅本地存储，服务于连续对话 | 核心 |
| 自然语言提醒（工具 `create_reminder`） | 工具总开关开启，首次调用询问 | 关闭工具总开关；或将授权改为“始终拒绝” | 产品既有核心能力 | 核心 |
| 会话自动摘要压缩上下文 | 开启（阈值 24 条） | 无单独开关；可删除会话 | 防止上下文超限导致失败 | 核心 |
| 托盘常驻与托盘菜单 | 开启 | 退出应用 | 窗口不可见于任务栏时的必要入口 | 核心 |
| 全局快捷键 `Ctrl+Shift+Space` | 注册（若被占用自动降级） | 不使用 / 退出 | 快速唤起聊天 | 核心 |
| 单实例运行 | 开启 | 无（结构约束） | 防止双托盘、双调度器 | 核心 |
| 低帧率模式（工作 / 睡眠 30fps） | 开启 | 设置 → 宠物与交互 | 降低空闲资源占用 | 性能 |

## 4. 工具调用的默认授权

工具总开关 `settings.toolSettings.enabled` 默认 `true`，但“工具可用”不等于“调用即执行”：

| 工具 | 默认授权 | 首次调用行为 | 出站 | 撤销位置 |
|---|---|---|---|---|
| `create_reminder` | 询问 | 弹出授权卡片 | 本地 | 设置 → 隐私 → 工具能力与授权 |
| `read_clipboard` | 询问 | 弹出授权卡片，说明内容会作为工具结果发回模型 | 本地读取，结果回传模型 | 同上 |
| `open_url` | 询问 | 弹出授权卡片 + 域名白名单校验 | 打开浏览器 | 同上；域名白名单可增删 |
| `open_app` | 询问 | 弹出授权卡片 + 固定应用白名单 | 本地启动 | 同上 |
| `get_weather` | **拒绝** | 直接拒绝并提示此前已拒绝 | 出站（Open-Meteo） | 设置为“每次询问 / 始终允许” |
| `web_search` | **拒绝** | 直接拒绝并提示此前已拒绝 | 出站（DuckDuckGo） | 同上 |

用户可在设置页逐项改为“每次询问 / 始终允许 / 始终拒绝”，并可随时关闭工具总开关。授权卡片默认不记忆；只有用户显式选择“始终允许 / 始终拒绝”才写入 `toolSettings.auth`。每次变更同时追加到 `toolSettings.grants`（最近 50 条），可在「隐私 → 授权历史」逐项撤销或一键撤销全部记忆授权（P-08）。

## 6. 新增默认开启的准入要求

1. 必须是核心链路的直接组成部分，或没有合理方式让用户先选择；
2. 必须有一键关闭路径，且关闭后不保留后台行为；
3. 必须在 PR 中更新本表，并在发布说明“新增”章节说明为何不能默认关闭；
4. 涉及敏感数据、系统权限或出站请求的，不得默认开启。

## 7. 版本对比口径

发布前由维护者对比本表与上一版本：

- 默认开启项数量增加 → 发布说明必须给出理由与关闭方式；
- 默认开启项减少 / 默认关闭 → 计入“收敛与移除”；
- 仅默认值调整 → 计入“安全与隐私变更”或“收敛与移除”，不得省略。
