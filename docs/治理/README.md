# DeskPet 治理基线

> 基线版本：v2.3.0（2026-11-13）
> 依据：[《DeskPet 后续开发规划文档》](../DeskPet%20后续开发规划文档.md) 第 5 节 P0 工作包
> 状态：M1 治理基线已交付（P-01 ~ P-05）
> 维护责任：项目维护者；涉及安全评审的条目由评审人共同签署

## 1. 这套文档解决什么问题

DeskPet 已经跨过“功能建设”阶段。后续最大的风险不是功能不够，而是：

1. 非核心功能默认开启，稀释“点击即聊”的核心体验；
2. 工具调用与系统集成不断扩大攻击面；
3. 安全承诺只停留在 README 的口号，无法验证、无法撤销；
4. 版本说明只讲新增，不讲移除，设计哲学无法延续。

本目录把上述约束固化为可执行的流程与可查阅的记录，而不是一次性文档。

## 3. 开发流程中的位置

```text
需求 / Issue
   │  填写《需求准入检查清单》六个问题
   ▼
准入判定（通过 / 条件通过 / 暂缓 / 拒绝）
   │  涉及新工具、感知源、系统集成点或新依赖
   ▼
安全评审（INT-xxx 记录，见 安全评审/）
   │  评审通过并登记后进入开发
   ▼
PR（.github/PULL_REQUEST_TEMPLATE.md 必须勾选准入与评审项）
   │  代码、测试、文档、默认值一并提交
   ▼
发布（按《发布说明规范》写新增 / 收敛移除 / 安全变更 / 验证）
```

**硬性规则：**

- 没有准入结论的需求不进入开发；
- 新增工具 / 感知源 / 系统集成点没有 `INT-xxx` 评审记录不合并；
- 发布说明缺少“收敛与移除”章节不发版（无内容时写“本版本无”）；
- 任何偏离核心且默认开启的能力，必须在《默认开启能力清单》登记并说明理由。

## 4. 安全承诺的验证入口

| 承诺 | 验证方式 |
|---|---|
| 密钥不进入渲染层、不进入数据文件与日志 | 《隐私与安全白皮书》第 4 节；`migrate_legacy_secrets`、`redact_secrets`；`cargo test` 脱敏用例 |
| 无遥测、无后台出站 | 《隐私与安全白皮书》第 6 节；设置页静态域名披露；`updateAuto` 默认关闭 |
| 工具调用可授权、可撤销 | 《工具调用能力边界》第 4 节；设置 → 隐私 → 工具能力与授权 |
| 不提供任意命令执行 / 文件读写 | 《工具调用能力边界》第 3 节；工具定义编译期固定 |
| 不引入通用插件 / 技能运行时 | [受限技能系统评估](../评估/受限技能系统评估.md)；仅保留数据扩展 |
| 每次发布说明新增与移除 | 《发布说明规范》；`scripts/check-governance.mjs` 校验 `docs/releases/*.md` 章节 |

## 5. 维护节奏

- 本目录随重大版本复审，至少每季度一次；
- 新增或修改工具、感知源、系统集成点时，同步新增 `INT-xxx` 记录，不修改历史结论；
- 隐私与安全白皮书随数据流、出站域名、密钥方案变化同步更新；
- 默认开启能力发生变化时，更新《默认开启能力清单》并在发布说明中说明原因；
- 所有重大取舍在发布说明或评审记录中留下决策理由。
