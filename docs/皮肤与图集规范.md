# 皮肤与图集规范（DeskPet v2.1+）

适用范围：内置皮肤、八态单图、`.deskpet-skin.zip` 皮肤包，以及设置页的皮肤管理与维护工具。

> **入口状态（v2.2.1 起）**：「导入单张图片」与「导入 Codex 宠物」两个入口**已屏蔽**——设置页不再提供按钮与文件选择框，渲染层不再注册对应导入逻辑，皮肤管理提示也已同步。仅保留「导入八态单图（4×2）」与「导入皮肤包（.deskpet-skin.zip）」两条导入路径；历史上已导入的单图形象与 Codex 宠物仍可切换、删除（Codex 条目只读展示，不再提供帧维护 / 导出）。第 3、6 节仅作格式参考与历史数据兼容说明。
> 实现位置：`src/settings.html`（导入 / 切割 / 维护）、`src/shared.js`（皮肤库与当前皮肤）、`src/pet.html`（运行时渲染）、`src-tauri/src/main.rs`（皮肤包与 Codex 包解析、导出）。

本文与代码中的常量、字段和校验顺序一一对应；调整阈值、契约或字段时，必须同步更新本文。

## 1. 皮肤体系总览

同一时间只有一个「当前皮肤」。设置保存在 `settings.skins[]` 列表中，`settings.activeSkin` 指向当前条目；运行时快照写入 `settings.skinPack` 或 `settings.customSkin` 供宠物窗口读取。

| 类型           | 入口                                      | 存储形态                                      | 状态来源           | 维护能力                                   |
| -------------- | ----------------------------------------- | --------------------------------------------- | ------------------ | ------------------------------------------ |
| 内置矢量皮肤   | 皮肤列表                                  | 代码内 SVG                                    | CSS 八态动画       | 无（仅切换）                               |
| 单图形象       | ~~导入单张图片~~（已屏蔽，仅历史数据）    | data URL                                      | 同一张图覆盖八态   | 创建皮肤包后逐状态维护                     |
| 八态单图       | 导入八态单图（4×2）                       | data URL × 8                                  | 固定 4×2 切割      | 同皮肤包                                   |
| DeskPet 皮肤包 | 导入皮肤包                                | `.deskpet-skin.zip` → 内存 `files` / `states` | `skin.json` 状态机 | 检查 / 修复 / 替换 / 清理 / 导出           |
| Codex 宠物     | ~~导入 Codex 宠物~~（已屏蔽，仅历史数据） | `pet.json` + 8×9 图集 → 行 / 帧               | 契约行 + 八态映射  | 只读展示（导入 / 维护 / 导出入口均已关闭） |

内置皮肤为 `团子蓝 / 橘猫 / 薄荷` 三套矢量形象（FR-SKN-001），不依赖图片资源。

## 2. 八态模型

DeskPet 运行时的状态集合固定为 8 个，顺序如下：

| 状态    | 界面文案 | 典型触发            | 运行时表现            |
| ------- | -------- | ------------------- | --------------------- |
| `idle`  | 待机     | 默认状态            | 呼吸 / 眨眼循环       |
| `drag`  | 拖拽     | 按住宠物拖动        | 摇摆循环              |
| `click` | 点击     | 单击宠物            | 挤压一次后回待机      |
| `talk`  | 说话     | 气泡打开 / 流式回复 | 口型或快速呼吸        |
| `sleep` | 睡眠     | 免打扰 / 空闲睡眠   | 慢速呼吸、Zzz         |
| `work`  | 工作     | 请求进行中          | 低频工作循环          |
| `happy` | 开心     | 正向反馈            | 跳跃 + 星光，约 1.9 s |
| `error` | 错误     | 请求失败 / 工具失败 | 抖动 + 汗滴，约 2.4 s |

通用回退规则：某个状态缺失时回退到 `idle`；`idle` 也缺失时整包导入报错或拒绝。皮肤包解析、八态单图切割和 Codex 映射都遵循这一规则。

## 3. 单图形象（不拆格）

入口：**已屏蔽**。设置页不再显示该按钮，`#skinFile` 文件控件也不在页面中；旧渲染层若仍投递文件，监听器直接丢弃并提示「该导入入口已关闭」，不调用 `petImageAnalyze`、不写入 `settings.skins`。下列规则仅用于理解历史数据与自动裁剪算法。

- 接受 `image/gif`、`image/png`、`image/webp`、`image/apng`，体积 ≤ 48 MB，长边 > 4096 时先等比缩到 4096 再分析。
- 导入时按 [`自动裁剪规范.md`](自动裁剪规范.md) 去掉四周留白与棋盘格底色，结果写入 `trim` 字段。
- 单图会覆盖全部八态；GIF / APNG / 动态 WebP 保留动画，但不逐帧裁切。
- 8×9 Codex 图集在普通入口会被识别并整幅保留，不会拆格；需要拆格请走 Codex 宠物导入。
- 单图本身不支持逐状态维护；点击「以当前图片创建皮肤包」可升级为八态结构后继续替换。

## 4. 八态单图（4×2 规则）

专用入口：设置页「导入八态单图（4×2 自动切割）」（**唯一保留的图片类导入入口**），只接收静态 PNG / WebP；GIF / APNG / 动态 WebP 会被拒绝。

### 4.1 排版契约

| 项       | 规则                                                        |
| -------- | ----------------------------------------------------------- |
| 布局     | 4 列 × 2 行，共 8 个彼此分离的角色                          |
| 读取顺序 | 按行读取：左上 → 右上，再左下 → 右下                        |
| 状态顺序 | `idle / happy / sleep / work / click / drag / error / talk` |
| 背景     | 透明，或与自动裁剪相同的浅色棋盘格 / 纯色底                 |
| 格内留白 | 允许，每格独立取内容包围盒                                  |
| 输出     | 8 张 PNG，统一画布，水平居中、底边对齐                      |

### 4.2 切割流水线

1. 复用自动裁剪的亮度 / 透明度分流 / 背景基调 / 行列投影，得到列段与行段。
2. 按内容像素总数各取前 4 列、前 2 行，再按坐标排序，过滤边缘噪点形成的碎段。
3. 在 4 × 2 交叉格内取内容包围盒；任一格内容少于碎屑阈值即报错，不产出缺状态的皮肤包。
4. 画布取 8 格内容的最大宽高，四周各加 4 px 透明内边距；每格水平居中、底边对齐，避免状态切换时角色上下跳动。
5. 生成八态皮肤包条目，状态映射为 `idle.png` ~ `talk.png`，并写入 `sheet` 元数据（布局、顺序、源文件名、画布尺寸）便于追溯。

### 4.3 验收数据

| 用例                                   | 输入                            | 期望                                 | 实测                                                                                            |
| -------------------------------------- | ------------------------------- | ------------------------------------ | ----------------------------------------------------------------------------------------------- |
| `assets/examples/eight-state-4x2.webp` | 1536×1536，4 列 × 2 行 8 个角色 | 识别 4 列 × 2 行并切成 8 张          | 列段 `[64,391] [431,751] [768,1095] [1112,1511]`；行段 `[168,720] [849,1392]`；统一画布 408×561 |
| 普通单图                               | 单角色 PNG                      | 专用入口提示「未识别出 4 列 × 2 行」 | 不生成皮肤包                                                                                    |
| 8×9 图集                               | 1536×1872 Codex 图集            | 拒绝并提示改用 Codex 宠物导入        | 不按八态切割                                                                                    |
| 动图                                   | GIF / APNG                      | 拒绝                                 | 提示改用静态 PNG / WebP                                                                         |

### 4.4 生成提示词（一图 8 状态）

给 AI 绘图工具时可直接使用下面的提示词，把方括号里的内容换成你的角色。产出必须满足 4.1 的排版契约：4 列 × 2 行、按行读取、状态顺序为 `idle / happy / sleep / work / click / drag / error / talk`，否则专用入口会拒绝或切错状态。

```text
一张专业的像素风精灵图集（Sprite Sheet），角色是 [替换为你的角色描述，如：一个可爱的森林小精灵]。透明背景。严格的 4列2行 网格布局，共 8 帧，从左到右、从上到下依次排列。每一帧尺寸完全相等，画布比例 1:1，角色在各帧中的大小比例、朝向和配色保持高度一致。
第一排（从左到右）：1. 待机，正面站立，表情平静，双手自然下垂；2. 开心，眼睛弯成弧形，张嘴微笑，脸颊泛红；3. 睡觉，闭眼，头部微微下垂偏向一侧，身体放松；4. 工作，低头专注，双手摆出敲击键盘的姿势，眉头微皱。
第二排（从左到右）：5. 被点击，身体轻微下压的挤压感，眼睛睁大，头顶有 2–3 个小星星或火花；6. 被拖拽，身体倾斜或悬空，双臂上举像被拎住，两侧有 2–3 条短运动线；7. 出错，眼睛变成 X 形或打转，嘴角下撇，额角有 1 滴汗或问号；8. 说话，张嘴呈说话状，眼睛活泼，嘴旁有 2–3 个小气泡或音符，但不要写任何文字。
2D像素艺术，扁平化设计，纯色色块，锐利的边缘，无抗锯齿，画面上没有网格线、没有文字、没有编号、没有任何分格边框。所有帧必须彼此分离，角色四周留出均匀的透明留白，相邻角色互不重叠。
```

画面对应关系（与第 2 节的运行时触发一一对应）：

| 帧  | 状态    | 何时出现在桌面上   | 出图重点                               |
| --- | ------- | ------------------ | -------------------------------------- |
| 1   | `idle`  | 默认待机           | 正面、平静，作为其他状态缺失时的回退图 |
| 2   | `happy` | 提醒触发等正向反馈 | 弯眼微笑、脸颊泛红                     |
| 3   | `sleep` | 免打扰 / 空闲睡眠  | 闭眼、身体放松，与 `idle` 区分明显     |
| 4   | `work`  | **等待模型回复**时 | 专注/思索，不要画成"摸鱼"              |
| 5   | `click` | 单击宠物的一瞬     | 挤压反馈，配星星或火花                 |
| 6   | `drag`  | 按住拖动时         | 悬空、双臂上举，配运动线               |
| 7   | `error` | 请求 / 工具失败    | X 眼、下撇嘴角、汗滴或问号             |
| 8   | `talk`  | 回复流式输出中     | 张嘴说话，配气泡或音符                 |

使用要点：

| 项                       | 说明                                                                                                                                                             |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 顺序不可调换             | 切割只按格子位置映射（`EIGHT_STATE_SHEET.order`），不读文件名：第二排第 1 格永远是被点击、第 2 格永远是被拖拽、第 3 格永远是出错、第 4 格永远是说话              |
| 画布与尺寸               | 提示词只要求「每帧尺寸完全相等」，不限定像素值；入口只校验 4 列 × 2 行与按行读取的顺序，长边超 4096 会先等比缩放。建议单格 512×512（整图 2048×1024）以保证清晰度 |
| 留白与对齐               | 每格独立取内容包围盒，再统一画布、水平居中、底边对齐（见 4.2）。各帧角色大小不一或站得高低不齐时，切换状态会看到角色跳动                                         |
| 互不重叠                 | 行列投影靠内容间隙分段，角色粘连会被识别成一个整体，报「未识别出 4 列 × 2 行」                                                                                   |
| 格式                     | 必须是静态 PNG / WebP；GIF / APNG 会被拒绝（逐格切割会丢帧）                                                                                                     |
| 透明背景                 | 提示词要求透明；若绘图工具只能给纯色或棋盘格底，切割时可自动剥离，规则见 [`自动裁剪规范.md`](自动裁剪规范.md) 第 8.2 节                                          |
| 不要网格线 / 文字 / 编号 | 格线、帧号、状态名都会被当作角色内容切进每帧                                                                                                                     |

生成后走设置页「导入八态单图（4×2 自动切割）」，可用第 9 节的 `assets/examples/eight-state-4x2.webp` 对照期望的切割结果。

## 5. `.deskpet-skin.zip` 皮肤包

### 5.1 包结构

```text
my-skin.deskpet-skin.zip
├─ skin.json            # 必需：名称、版本、状态机
├─ idle.png             # 八态图片（png / gif / webp）
├─ happy.png
├─ …                    # 其余状态图
├─ ding.ogg             # 可选音效（ogg / mp3 / wav）
└─ group/…              # 可选：分组资源，按 basename 引用
```

压缩包内所有条目只按 basename 处理；带目录的条目会被展平，路径穿越（`../`）无法落到包外。图片统一转为 data URL 持有，音效单独存入 `sounds`。

### 5.2 `skin.json`

| 字段      | 必需       | 类型   | 说明                                                   |
| --------- | ---------- | ------ | ------------------------------------------------------ |
| `name`    | 是         | string | 展示名，最长 40 字符；为空则拒绝导入                   |
| `version` | 否         | string | 版本号，默认 `1.0`                                     |
| `states`  | 否（推荐） | object | 八态 → 包内文件名；缺失或引用不存在的文件时回退 `idle` |
| `group`   | 否         | object | 分组 → 文件名，仅保留真实存在的资源                    |
| `sound`   | 否         | object | 音效键 → 文件名；`reminder` 用于提醒提示音             |

状态机校验规则：

- 按 `idle / drag / click / talk / sleep / work / happy / error` 顺序补齐；缺失或引用不存在的文件时回退到 `idle.png`（无 `idle.png` 时取包内第一张图片）。
- 所有状态都无可用图片时拒绝导入。
- 未知状态键在维护时忽略，不写入运行时状态机。

最小示例：

```json
{
  "name": "圆头小猫",
  "version": "1.0",
  "states": {
    "idle": "idle.png",
    "drag": "drag.png",
    "click": "click.png",
    "talk": "talk.png",
    "sleep": "sleep.png",
    "work": "work.png",
    "happy": "happy.png",
    "error": "error.png"
  },
  "sound": { "reminder": "ding.ogg" }
}
```

### 5.3 导入校验

| 项           | 限制                      |
| ------------ | ------------------------- |
| 压缩包体积   | ≤ 128 MB                  |
| 单文件解压后 | ≤ 64 MB                   |
| 解压总大小   | ≤ 256 MB                  |
| 条目数       | ≤ 200                     |
| `skin.json`  | 必须是 UTF-8 JSON 对象    |
| 图片类型     | `.png` / `.gif` / `.webp` |
| 音效类型     | `.ogg` / `.mp3` / `.wav`  |

### 5.4 导出

「导出当前皮肤（.zip）」重新生成 `skin.json`，只写入标准八态中真实存在且被引用的图片；音效按 `sound` 键输出为 `键.ogg|mp3|wav`。导出的包可直接重新导入任意 DeskPet。

## 6. Codex Pet Contract（导入入口已屏蔽，仅格式参考）

设置页的「导入 Codex 宠物」按钮、`#codexPetFile` 文件控件与「导出为 Codex 宠物」按钮均已移除，`invoke('codex_pet_import')` 不再从渲染层调用；主进程 `codex_pet_import` / `codex_pet_export` 命令保留仅为兼容历史代码与回归测试。历史已导入的 Codex 条目可在皮肤管理中查看、切换、删除，维护面板只显示「来自历史数据」提示，不再渲染帧级维护。

### 6.1 来源与目录

Codex 桌面端的自定义宠物位于 `${CODEX_HOME:-~/.codex}/pets/<pet-id>/`：

```text
pets/codex-round-cat/
├─ pet.json
└─ spritesheet.webp
```

导入时把该目录打包为 zip；也支持包内直接带 `pet.json` 与图集的任意 zip。

### 6.2 `pet.json`

| 字段                  | 必需                   | 说明                                |
| --------------------- | ---------------------- | ----------------------------------- |
| `id`                  | 是（或 `displayName`） | 宠物 ID，导入时规范化为 slug        |
| `displayName`         | 是（或 `id`）          | 展示名，最长 40 字符                |
| `description`         | 否                     | 描述，最长 240 字符                 |
| `spritesheetPath`     | 否                     | 图集文件名，默认 `spritesheet.webp` |
| `version` / `license` | 否                     | 元数据，原样保留                    |

`spritesheetPath` 只取 basename；声明文件不存在时，会在包内寻找尺寸符合 1536×1872 的同类型图片。

### 6.3 图集契约

| 项         | 值                             |
| ---------- | ------------------------------ |
| 总尺寸     | 1536 × 1872 px                 |
| 网格       | 8 列 × 9 行                    |
| 单格       | 192 × 208 px                   |
| 背景       | 透明；未使用的格子必须完全透明 |
| 可用格式   | PNG / WebP / GIF / SVG         |
| 单文件上限 | 64 MB                          |

行序固定，不能调整：

| 行  | 名称            | 含义     | 帧上限 |
| --- | --------------- | -------- | ------ |
| 0   | `idle`          | 待机     | 6      |
| 1   | `running-right` | 向右跑   | 8      |
| 2   | `running-left`  | 向左跑   | 8      |
| 3   | `waving`        | 挥手     | 4      |
| 4   | `jumping`       | 跳跃     | 5      |
| 5   | `failed`        | 失败     | 8      |
| 6   | `waiting`       | 等待输入 | 6      |
| 7   | `running`       | 处理中   | 6      |
| 8   | `review`        | 审查     | 6      |

- PNG 按 8×9 网格切片，SVG 通过 `viewBox` 分组裁切，两者都按行的契约上限取帧，未使用的格子保持透明。
- WebP / GIF 视为单幅动画（社区 Codex 宠物常见形式）：整幅按 1 行 1 帧播放，等比缩放进 192×208 格，不做逐行切片；图集尺寸仍须为 1536×1872。
- 单行来源会把全部八态映射到该行；GIF 帧时长从图形控制扩展读取，缺省 120 ms。

### 6.4 八态映射

导入时按行合并同义动作，缺失状态回退 `idle`：

| DeskPet 状态 | Codex 行               |
| ------------ | ---------------------- |
| `idle`       | `idle`                 |
| `drag`       | `running-right`        |
| `click`      | `jumping`              |
| `talk`       | `waiting`              |
| `sleep`      | `idle`（契约无睡眠行） |
| `work`       | `running`              |
| `happy`      | `waving`               |
| `error`      | `failed`               |

只有一行有效帧的 Codex 包（例如单行动画 WebP）会把全部八态都映射到该行。

运行时按当前状态找到对应行，再按 `durations[col]` 逐帧播放，末帧回到第 0 帧；帧时长可在维护工具中逐行修改（20–5000 ms）。

### 6.5 导出

「导出为 Codex 宠物（pet.json + spritesheet.png）」将当前皮肤还原为契约包：

- 输出 1536×1872 透明 PNG 图集与 `pet.json`，写入 `%APPDATA%\com.mrtransition.deskpet\exports\codex-pets\<id>\`。
- 有逐帧记录时按原帧、原行还原；其余来源按八态映射回填，单图等比缩放并贴底到 192×208，保持同一地面线。
- 缺失且无映射的行用 `idle` 填充；完全没有任何可用图片时导出失败。
- 未使用的格子保持全透明。

## 7. 导入闸门与安全限制

> 当前生效的导入通道只有「八态单图」与「皮肤包」；下表图片预处理适用于八态单图（及历史单图数据），Codex 行仅作参考。

| 层              | 规则                                                                              |
| --------------- | --------------------------------------------------------------------------------- |
| 图片预处理      | 类型白名单；≤ 48 MB；长边 ≤ 4096（超出先缩放）                                    |
| 皮肤包 / 宠物包 | zip ≤ 128 MB；条目 ≤ 200；单文件 ≤ 64 MB；解压总计 ≤ 256 MB                       |
| 路径安全        | 仅取 basename，拒绝 `.` 开头与含 `/`、`\` 的条目；导出文件名过滤 Windows 保留字符 |
| 清单解析        | 必须是 UTF-8 JSON 对象；缺失 `skin.json` / `pet.json` 直接拒绝                    |
| 契约校验        | Codex 图集必须 1536×1872；行序、帧上限、`spritesheetPath` 扩展名逐项检查          |
| 渲染安全        | SVG 图集清洗脚本、事件属性与外链；图片以 data URL 注入，不发起网络请求            |
| 失败策略        | 校验失败不写入皮肤库，不覆盖当前皮肤                                              |

## 7bis. 皮肤包导入规范与自检清单

本节是「导入皮肤包」入口的可执行验收规范：怎么打包、会被哪些规则拒绝、以及怎么在校验功能正常。

### 7bis.1 打包步骤

```powershell
# 目录结构（压缩包的根目录就是这些条目，不要多套一层文件夹）
my-skin/
├─ skin.json
├─ idle.png  happy.png  sleep.png  work.png
├─ click.png drag.png   error.png  talk.png
└─ ding.ogg            # 可选
# 全选后右键「发送到 → 压缩(zipped) 文件夹」，改名为 my-skin.deskpet-skin.zip
```

- `skin.json` 必须是 **UTF-8 无 BOM** 的 JSON 对象；`name` 必填（≤40 字符），`states` 用文件名映射八态。
- 图片文件名与 `states` 里的值逐字符一致（大小写敏感，建议全小写 ASCII）；不要出现中文名、空格、`#`、`?`。
- 音效键 `reminder` 对应提醒提示音，可省略。
- 不要压缩成 *压缩文件内的压缩文件*，也不要在包内放 `__MACOSX/`、`.git/` 等隐藏目录。

### 7bis.2 会被拒绝的输入（错误文案可直接用于核对）

| 输入                             | 主进程校验                | 预期提示                                       |
| -------------------------------- | ------------------------- | ---------------------------------------------- |
| 非 zip 文件（改扩展名的 png 等） | `ZipArchive::new` 失败    | 不是有效的皮肤包（zip）：…                     |
| zip 体积 > 128 MB                | 导入前 + 主进程各校验一次 | 皮肤包超过 128 MB / 皮肤包超过 128 MB 上限     |
| 条目数 > 200                     | `zip.len()`               | 皮肤包条目过多                                 |
| 单文件解压 > 64 MB               | `f.size()`                | `xxx.png` 超过 64 MB 单文件上限                |
| 解压总计 > 256 MB                | 累计 `total`              | 皮肤包解压后总大小超限                         |
| 缺少 `skin.json`                 | `manifest` 为空           | 皮肤包缺少 skin.json                           |
| `skin.json` 非 UTF-8 / 非法 JSON | 解码 + `serde_json`       | skin.json 不是 UTF-8 文本 / skin.json 解析失败 |
| `name` 缺失或空白                | `trim().is_empty()`       | skin.json 缺少 name                            |
| 包内没有任何 png / gif / webp    | `states` 为空             | 皮肤包里没有任何图片资源                       |
| 导出时 `states` 全部失效         | `skin_zip_bytes`          | 导出前提示状态为空（不会产出坏包）             |

不会拒绝、但会被静默修正的情况：

| 情况                                        | 行为                                                                          |
| ------------------------------------------- | ----------------------------------------------------------------------------- |
| 带目录的条目（`group/idle.png`）            | 只取 basename，展平处理；`../` 无法落到包外                                   |
| 条目名以 `.` 开头或含 `/`、反斜杠分隔符     | 跳过该条目                                                                    |
| `states` 引用了包内不存在的文件             | 该状态回退到 `idle.png`；无 `idle.png` 时回退到包内第一张图片                 |
| `states` 缺键 / 键名大小写不符（如 `Idle`） | 按 `idle / drag / click / talk / sleep / work / happy / error` 顺序补齐并回退 |
| `group` 引用了不存在的文件                  | 该分组键被忽略                                                                |
| `version` 缺失                              | 使用默认 `1.0`                                                                |

### 7bis.3 校验功能是否正常（四层，按从快到慢）

1. **单元 / 契约测试**（毫秒级，CI 必跑）

   ```powershell
   cargo test --manifest-path src-tauri/Cargo.toml
   ```

   关注用例：`skin_pack_parses_manifest_and_states`、`skin_pack_rejects_missing_manifest_and_bad_name`、`skin_pack_export_roundtrip`、`repo_sample_skin_pack_parses`、`skin_zip_rejects_empty_states`，以及屏蔽入口的 `skin_management_hides_image_and_codex_import`。

2. **示例包正向回归**：重新构建后（`src/` 会被嵌入二进制，改文案后必须 `cargo build`）启动应用 → 设置 → 宠物与交互 →

   - 只应看到「导入八态单图」「导入皮肤包」「恢复内置矢量皮肤」三个按钮，**不应**出现「导入单张图片」与「导入 Codex 宠物」；
   - 导入 `assets/skin-packs/round-cat.deskpet-skin.zip` → 提示「已导入皮肤包：圆头小猫（8 个状态）」，皮肤卡片出现缩略图并自动切换；
   - 维护工具显示「8 张图片 · ✓ 八态映射与资源引用完整」。

3. **反向用例**：分别投递上面 7bis.2 表格里的坏包，逐条比对提示文案；任何一种情况下皮肤列表条数都不应变化、当前皮肤也不应被覆盖。

4. **完整链路（可选）**：`皮肤导出（.zip）` → 把导出的包再导入，`read_skin_zip → skin_zip_bytes → read_skin_zip` 必须稳定往返（`skin_pack_export_roundtrip` 已覆盖）。

> 注意：`src/` 下静态资源通过 `include_str!`/内置资源嵌入程序，只改 HTML / i18n 后必须重新 `cargo build`（或 `npm run tauri dev`），否则运行的仍是旧页面。

## 8. 皮肤管理与维护工具

### 8.1 皮肤管理（查看 / 切换 / 删除）

设置页「宠物与交互 → 皮肤管理」列出全部**导入**皮肤，每行显示缩略图、名称、类型（单图形象 / 皮肤包 / Codex 宠物）与数据体积，并提供两个操作：

| 操作 | 行为                                                                                                                     |
| ---- | ------------------------------------------------------------------------------------------------------------------------ |
| 使用 | 切换为该皮肤，等价于皮肤卡片点击                                                                                         |
| 删除 | 二次确认后移除条目；若删除的是**正在使用**的皮肤，同时清空 `activeSkin` / `skinPack` / `customSkin` 并回退到内置矢量皮肤 |

删除约束：内置 3 套皮肤不在列表中、不可删除；删除会清除该皮肤在 `data.json` 中的全部图片数据，不可恢复，需要重新导入。

### 8.2 维护工具

设置页「宠物与交互 → 皮肤维护工具」直接编辑当前皮肤条目：

| 操作                 | 适用对象       | 行为                                                                     |
| -------------------- | -------------- | ------------------------------------------------------------------------ |
| 重新检测             | 皮肤包 / Codex | 重新渲染八态映射、资源引用与契约检查结果                                 |
| 修复状态映射         | 皮肤包         | 缺失或失效的状态回退到可用 `idle`，并报告修复项                          |
| 逐状态替换           | 皮肤包         | 为单个状态选择新图片，自动生成不冲突的文件名                             |
| 批量导入八态图片     | 皮肤包         | 按文件名匹配 `idle / drag / click / talk / sleep / work / happy / error` |
| 清理未引用资源       | 皮肤包         | 删除未被 `states` / `group` 引用的图片，操作前二次确认                   |
| 以当前图片创建皮肤包 | 单图           | 就地升级为八态皮肤包，不产生重复条目                                     |
| 修改名称 / 版本      | 皮肤包 / 单图  | 名称最长 40 字符，版本最长 24 字符                                       |
| 导出当前皮肤         | 皮肤包 / 单图  | 皮肤包导出 `.zip`；单图导出原始图片                                      |
| Codex 帧维护         | Codex          | 点击帧替换、追加帧、删除末帧、逐行修改帧时长                             |
| Codex 状态复用       | Codex          | 为每个 DeskPet 状态选择播放哪一行                                        |
| 导出为 Codex 宠物    | 任意可渲染皮肤 | 生成契约图集与 `pet.json`                                                |

维护结果写入 `settings.skins[]` 并立即持久化；导出前可用「清理未引用资源」减小包体，但清理不可撤销，建议先导出备份。

## 10. 常见问题

| 现象                                             | 原因                                                | 处理                                                                                      |
| ------------------------------------------------ | --------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 八态单图提示「未识别出 4 列 × 2 行」             | 角色数量不足、行列间距过小或背景与角色亮度接近      | 按 4×2 重新排版，保证 8 个角色彼此分离且与背景有对比                                      |
| 八态单图导入被拒                                 | 使用了 GIF / APNG / 动态 WebP                       | 改为静态 PNG / WebP                                                                       |
| 设置页看不到「导入单张图片」/「导入 Codex 宠物」 | 两个入口已按产品要求屏蔽                            | 改用「导入八态单图」或「导入皮肤包」                                                      |
| Codex 导入提示尺寸不符                           | 图集不是 1536×1872                                  | 按 8 列 × 9 行、单格 192×208 重新导出                                                     |
| Codex 导入提示缺少 `pet.json`                    | 误用了 `.deskpet-skin.zip` 入口或包内清单缺失       | 确认入口与清单文件；DeskPet 皮肤包请走「导入皮肤包」                                      |
| 某状态一直显示待机                               | 该状态映射缺失或引用了不存在的文件                  | 用「修复状态映射」或逐状态替换补图                                                        |
| 点击宠物时显示成「惊吓」、出错时显示成「思考中」 | 八态单图第二排状态顺序被调换                        | 按 4.1 / 4.4 的顺序重排：第 5 格 `click`、第 6 格 `drag`、第 7 格 `error`、第 8 格 `talk` |
| 状态切换时角色上下跳、忽大忽小                   | 各帧角色比例或基线不一致，统一画布后仍不齐          | 出图时锁定同一角色比例与站立基线，见 4.4「留白与对齐」                                    |
| 皮肤包导入提示超限                               | 超过 128 MB / 单文件 64 MB / 解压 256 MB / 200 条目 | 压缩图片或拆分资源后重试                                                                  |
| 导入后角色被裁掉一部分                           | 素材边缘与背景对比过弱，或使用了整幅图集            | 参见 [`自动裁剪规范.md`](自动裁剪规范.md) 的已知局限，改用透明底素材                      |
