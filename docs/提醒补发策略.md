# 提醒补发策略（FR-REM-008）

> 状态：v2.3.5 落地
> 关联需求：FR-REM-008、AC-025
> 入口：设置 → 宠物与交互 → 提醒与免打扰

## 1. 为什么需要明确策略

提醒由主进程调度器每秒检查一次。应用退出、系统休眠、跨时区或夏令时（DST）切换后，提醒的到期时间可能已经过去。若不定义策略，会出现两类问题：

- 重启后把很久以前的提醒全部补播，造成打扰；
- 重复提醒被静默跳过，或同一提醒被反复触发。

v2.3.5 起使用「最多补发一次 + 明确时间上限」的策略，并允许用户关闭补发。

## 2. 术语与默认值

| 项 | 默认值 | 说明 |
|---|---|---|
| 调度抖动容忍 | 90 秒 | 应用运行中正常的秒级延迟，始终视为准时 |
| 补发开关 | **开启** | 关闭后，真正错过的提醒不播报 |
| 补发上限 | **1440 分钟（24 小时）** | 超过上限的提醒不播报；范围 1–10080 分钟（7 天） |
| 同一提醒补发次数 | 1 次 | 无论重启 / 休眠恢复多少次，都不会重复播报已补发过的提醒 |

设置项：`settings.reminderCatchUp`（布尔）与 `settings.reminderCatchUpMin`（整数分钟）。旧数据缺少字段时按默认值处理，不迁移、不写回。

## 3. 各场景行为

| 场景 | 行为 |
|---|---|
| 应用正常运行，晚 1–2 秒 | 正常播报 |
| 应用退出后重启，提醒刚过期 10 分钟 | 补发一次（在 24 小时上限内） |
| 应用退出后重启，提醒已过期 3 天 | 不补发；一次性提醒移除，重复提醒顺延到下一个未来时间 |
| 系统休眠 2 小时后恢复 | 调度线程检测到中断并记录 `reminder.resume_gap`；到期提醒按上限补发一次 |
| 关闭补发开关 | 只有 90 秒内视为准时的提醒播报；其余跳过并顺延 / 移除 |
| 免打扰时段内到期 | 先进入免打扰队列，结束后统一播报；应用在队列未清空时退出则不再恢复该队列（避免重复） |
| 时区变化 | `due` 是绝对时间戳，时区切换不改变到期时刻，也不会重复触发 |
| 跨 DST | 每日 / 每周按固定绝对间隔推进，墙体时间最多偏移 1 小时；不会重复触发 |

## 4. 重复提醒的顺延

- `daily`：+24 小时；
- `weekly`：+7 天；
- `interval`：+ `intervalMin` 分钟（非法值按 1 分钟兜底）；
- 一次性提醒：播报或跳过后移除。

顺延始终推进到严格晚于当前时间的下一次，因此即使休眠数天，也只会补发一次，不会连续弹出多条历史提醒。

## 5. 日志与隐私

| 事件 | 级别 | 内容 |
|---|---|---|
| `reminder.skipped` | info | 仅记录被跳过的条数，不含提醒正文 |
| `reminder.resume_gap` | info | 仅记录调度中断的秒数，不含系统或用户信息 |

补发策略完全在本地执行，不产生网络请求，不读取系统时区名称或硬件信息。

## 6. 边界与未覆盖项

- 免打扰队列只在内存中保存，应用退出后不恢复；这是为了避免退出/重启造成重复播报。
- 时区与 DST 采用「绝对时间锚定」策略：不尝试重建用户所在时区的墙体时间；跨 DST 的每日提醒可能偏移 1 小时。
- 不提供按提醒单独配置补发策略；上限是全局设置。
- 不补发应用完全未运行期间创建的提醒（提醒本身只存在于本机数据文件）。

## 7. 验证

自动化测试（`cargo test`）：

- `reminders_fire_before_reschedule`：重复提醒先触发再顺延；
- `reminders_disabled_and_far_past`：禁用的提醒不触发，超过 24 小时的提醒被跳过；
- `reminders_catch_up_once_and_respect_limit`：上限内补发一次，超限跳过，关闭补发后不播报但仍顺延；
- `reminders_tick_jitter_still_fires_when_catch_up_off`：秒级抖动不受补发开关影响。

手工验收：

1. 创建 1 分钟后的一次性提醒，退出应用，2 分钟后重启 → 播报一次；
2. 将系统时间向前调整 2 天（或导入过期提醒）→ 重启后不播报，重复提醒顺延；
3. 关闭「错过提醒后补发一次」，重复步骤 1 → 不播报；
4. 观察日志出现对应的 `reminder.skipped` / `reminder.resume_gap`（如适用），且不含提醒正文。
