# DeskPet 后续开发路线图

> 基线版本：v2.1.2（2026-11-10）
> 需求依据：[SRS v1.2](../桌面%20AI%20宠物软件需求规格说明书（SRS）.md)
> 维护方式：每个里程碑完成后更新状态、验收结果与版本号。

## 1. 现状判断

v2.1.0 已覆盖 SRS 的大部分核心功能，但按 v1.1 的 P0/P1 口径，仍有若干“已宣称完成、实际部分交付”的项和工程基础缺口。剩余工作集中在三类：

1. **P0/P1 名实不符项**（单实例、首次引导、CSP、备份恢复等）；
2. **体验与合规缺口**（i18n、更新签名、无障碍、日志轮转）；
3. **工程化与数据层升级**（SQLite/FTS、安装器、模块化、CI）。

当前最值得优先处理的不是继续堆新功能，而是先补齐 v1 验收基线中的 P0/P1 缺口，再进入多模态与跨平台阶段。P2 不阻塞发布，P3 仅登记不排期。

## 3. 里程碑

### v2.2.0 — 合规与体验补全（约 7–10 天）

目标：不改架构，先补齐 v1 验收基线中的 P0/P1 缺口，再处理 P2 体验项，让交付说明与实现一致。

- [ ] **单实例运行（FR-SYS-007，P0）**
  - 引入单实例插件或命名互斥量；
  - 重复启动时唤起已有宠物/气泡窗口；
  - 验收：不产生第二套托盘与提醒调度器。
- [ ] **首次启动引导（FR-SYS-008，P0）**
  - 首次启动展示 3 步引导：选择模型 → 填写 Key / 本地地址 → 隐私与数据位置告知；
  - 敏感能力（剪贴板、截图、ASR）默认关闭并说明；
  - 支持跳过，之后可从设置页重新打开。
- [ ] **完整中英 i18n（FR-SYS-006，P2）**
  - 抽取 `src/settings.html`、`src/bubble.html`、`src/pet.html` 全部静态文案；
  - 统一 `data-i18n` / `data-i18n-title` / `data-i18n-ph` 与 `t()` 机制；
  - 语言切换即时生效，无需重启；
  - 验收：英文界面除用户内容、模型名、供应商名外无残留中文。
- [x] **系统代理遵循（FR-MDL-008，P2）**
  - v2.1.2 起不提供应用内代理配置；网络请求遵循操作系统代理设置，设置页不再新增代理输入。
- [ ] **更新安全（NFR-SEC-004、FR-SYS-009）**
  - 更新清单增加 `sha256` 与 `signature`；
  - 下载后校验哈希，签名不匹配直接拒绝；
  - 失败时保留当前版本并提示，不阻断启动；
  - 继续坚持“只下载、不静默安装”。
- [ ] **CSP 与渲染安全（NFR-SEC-005、FR-BUB-018）**
  - 启用内容安全策略，限制脚本、样式、图片与连接来源；
  - 复核 Markdown 链接协议白名单与代码块转义；
  - 验收：注入脚本不执行，外链图片不自动加载。
- [x] **移除自定义请求头（NFR-SEC-006、DS-004）**
  - v2.1.2 已删除供应商编辑中的请求头输入；旧配置不再产生新的明文敏感头，导出与日志继续脱敏。
- [ ] **备份恢复与会话管理（FR-DAT-005、FR-DAT-006）**
  - 增加数据模式版本号与迁移入口；
  - 一键备份/恢复，迁移失败保留原数据并回滚；
  - 会话重命名、批量删除与二次确认。
- [ ] **无障碍与硬件加速（NFR-UI-004、NFR-INT-006）**
  - 键盘导航、可见焦点、基础 ARIA 语义；
  - 设置项持久化，下次启动通过 WebView2 参数关闭 GPU；
  - 适配系统字体缩放与高对比度模式。
- [ ] **提醒补发策略（FR-REM-008）**
  - 明确睡眠、重启、时区/DST 变化后的补发上限；
  - 同一提醒不重复触发，补发需可配置。
- [ ] **日志轮转（NFR-MNT-003）**
  - 最大体积、保留份数/天数；
  - 超限自动轮转，不影响主流程。
- [ ] **自动清理策略（DR-002）**
  - 30 / 90 / 180 天，默认关闭；
  - 执行前二次确认并说明影响范围。
- [ ] **性能基线（NFR-PERF-001~008）**
  - 实测冷启动、气泡弹出、空闲 CPU/内存、安装包体积、1 万条消息检索；
  - 输出 `docs/PERF.md`，记录测试机、系统版本、构建类型与数据集；
  - 将 NFR-PERF-007 从“待实测”改为“已实测”。
- [ ] **发布前检查**
  - `cargo test`、JS 语法检查、CDP E2E、更新清单校验；
  - 同步更新 README、SRS 状态表与版本号。

### v2.3.0 — 数据层与工程化（约 2–3 周）

- [ ] **数据管理增强（DR-001~004、DS-001~003）**

## 4. 建议执行顺序

如果只做一轮，建议按以下顺序：

1. **单实例 + 首次引导** — P0 验收缺口，风险低、用户可见；
2. **CSP + 隐私披露** — 安全项，先于新功能；
3. **更新签名与失败回退** — 安全项，避免篡改与更新阻断；
4. **备份恢复 + 会话批量管理** — 数据安全与可用性；
5. **i18n 补全** — 体验补齐；
6. **性能基线报告** — 把已有成果变成可验收数据；
7. **SQLite 技术验证** — 先做 1–2 天 spike，再决定 v2.3 排期。

暂不建议同时启动 ASR、截图分析和 Live2D，这三项都会显著增加包体、隐私评审和运行时复杂度。

## 6. 完成定义（Definition of Done）

每个里程碑需同时满足：

- 需求对应的 SRS 条目状态已更新；
- `cargo test` 全绿，新增行为有回归测试；
- 前端 4 个 script 块通过语法检查；
- 关键路径通过 CDP 运行时 E2E；
- 涉及安全/隐私的改动完成代码审查与日志脱敏检查；
- README、版本号、更新清单与发布产物一致；
- 性能相关需求有实测数据与报告。

## 7. 风险与应对

| 风险 | 应对 |
|---|---|
| SQLite 迁移导致数据损坏 | 迁移前自动备份、双写/只读校验、失败回滚、保留 `data.json` |
| i18n 文案遗漏或键冲突 | 统一命名规范，增加“英文界面无中文残留”自动检查 |
| 更新签名密钥管理复杂 | 固定签名方案与发布流程，私钥离线保存，CI 仅持有公钥 |
| ASR 模型体积与授权 | 优先系统语音/本地小模型，做成可选下载组件 |
| Live2D 授权与包体 | 先 Lottie，Live2D 单独评估，不阻塞主版本 |
| 多平台适配成本 | 核心逻辑与平台能力解耦，按 Windows → macOS → Linux 推进 |
