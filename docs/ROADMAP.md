# DeskPet 后续开发路线图

> 基线版本：v2.1.0（2026-11-04）
> 需求依据：[SRS](../桌面%20AI%20宠物软件需求规格说明书（SRS）.md)
> 维护方式：每个里程碑完成后更新状态、验收结果与版本号。

## 1. 现状判断

v2.1.0 已覆盖 SRS 的主要 P0 功能，剩余工作集中在三类：

1. **已宣称完成、但实际不完整**的项；
2. **P1/P2 体验与合规缺口**；
3. **工程化与数据层升级**。

当前最值得优先处理的不是继续堆新功能，而是先补齐“名实不符”的缺口，再进入多模态与跨平台阶段。

## 3. 里程碑

### v2.2.0 — 合规与体验补全（约 5–7 天）

目标：不改架构，快速补齐可见缺口，让 v2.x 的交付说明与实现一致。

- [ ] **完整中英 i18n**
  - 抽取 `src/settings.html`、`src/bubble.html`、`src/pet.html` 全部静态文案；
  - 统一 `data-i18n` / `data-i18n-title` / `data-i18n-ph` 与 `t()` 机制；
  - 语言切换即时生效，无需重启；
  - 验收：英文界面除用户内容、模型名、供应商名外无残留中文。
- [ ] **代理配置 UI（FR-MDL-008）**
  - 供应商编辑页新增代理类型（自动 / HTTP / SOCKS5）与代理地址；
  - 保存/加载 `proxy`、`proxyType`，连通性测试走代理；
  - 后端逻辑已存在，主要是前端接线与回显。
- [ ] **更新安全（NFR-SEC-004）**
  - 更新清单增加 `sha256` 与 `signature`；
  - 下载后校验哈希，签名不匹配直接拒绝；
  - 继续坚持“只下载、不静默安装”。
- [ ] **硬件加速开关 + 高对比度（NFR-UI-002）**
  - 设置项持久化，下次启动通过 WebView2 参数关闭 GPU；
  - 适配系统字体缩放与高对比度模式。
- [ ] **自动清理策略（DR-002）**
  - 30 / 90 / 180 天，默认关闭；
  - 执行前二次确认并说明影响范围。
- [ ] **性能基线（NFR-PERF-001~008）**
  - 实测冷启动、气泡弹出、空闲 CPU/内存、安装包体积、1 万条消息检索；
  - 输出 `docs/PERF.md`，将 NFR-PERF-007 从“待实测”改为“已实测”。
- [ ] **发布前检查**
  - `cargo test`、JS 语法检查、CDP E2E、更新清单校验；
  - 同步更新 README、SRS 状态表与版本号。

### v2.3.0 — 数据层与工程化（约 2–3 周）

目标：解决 JSON 存储的长期瓶颈，为后续多模态功能打基础。

- [ ] **SQLite 迁移（FR-DAT-001）**
  - 表：providers / personas / sessions / messages / memories / reminders / settings；
  - 密钥仍只存系统凭据管理器，数据库仅存引用；
  - WAL、事务、外键、索引；
  - 从 `data.json` 自动迁移并保留备份，支持失败回滚。
- [ ] **FTS5 全文检索（FR-DAT-002、NFR-PERF-008）**
  - 消息增量索引，支持标题 + 内容检索；
  - 1 万条消息检索 ≤ 500 ms；
  - 替换当前前端 `includes()` 线性扫描，检索结果分页。
- [ ] **数据管理增强（DR-001~004、DS-001~003）**
  - 全量导出/导入、增量备份、完整性检查；
  - 自动清理与保留策略落地。
- [ ] **主进程模块化（NFR-CON-004、NFR-MNT-002）**
  - 将 `src-tauri/src/main.rs` 拆为 `provider / chat / tools / reminders / state / update / log / skin`；
  - 保持行为不变，补集成测试。
- [ ] **安装包与卸载（DS-003）**
  - 启用 Tauri NSIS/MSI，按用户安装、无需管理员权限；
  - 卸载时询问保留或删除用户数据。
- [ ] **CI / Release（NFR-MNT-001）**
  - GitHub Actions：`cargo test`、JS 检查、release 构建；
  - 发布清单、校验和、签名、GitHub Releases。

### v3.0.0 — 多模态与动画运行时（约 4–6 周，建议只选 1–2 项）

- [ ] **ASR 语音输入（FR-VOI-001）**
  - 优先评估 whisper.cpp / Windows 系统语音；
  - 默认关闭、按键说话、语言选择、失败回退文本输入。
- [ ] **截图分析（FR-TOOL-002、NFR-PRV-003）**
  - 按次授权、区域选择、发送前预览；
  - 默认本地 OCR，确认后才上传模型。
- [ ] **动画运行时（FR-PET-009、TBD-01）**
  - 先做 Lottie（体积小、JSON 资源、风险低）；
  - Spine 次之，Live2D 最后（SDK 授权与包体风险最高）；
  - 同步决策 TBD-01。
- [ ] **记忆检索升级（FR-MEM-002、TBD-03）**
  - 先做关键词 + 时间衰减的基线评测；
  - 再评估本地向量检索，避免过早引入 embedding 模型和包体膨胀。

## 4. 建议执行顺序

如果只做一轮，建议按以下顺序：

1. **i18n 补全** — 用户可见、风险低；
2. **代理 UI** — 后端已完成，半天到一天；
3. **更新签名** — 安全项，优先于新功能；
4. **性能基线报告** — 把已有成果变成可验收数据；
5. **SQLite 技术验证** — 先做 1–2 天 spike，再决定 v2.3 排期。

暂不建议同时启动 ASR、截图分析和 Live2D，这三项都会显著增加包体、隐私评审和运行时复杂度。

## 6. 完成定义（Definition of Done）

每个里程碑需同时满足：

- 需求对应的 SRS 条目状态已更新；
- `cargo test` 全绿，新增行为有回归测试；
- 前端 4 个 script 块通过语法检查；
- 关键路径通过 CDP 运行时 E2E；
- 涉及安全/隐私的改动完成代码审查与日志脱敏检查；
- README、版本号、更新清单与发布产物一致；
- 性能相关需求有实测数据与报告。

## 7. 风险与应对

| 风险 | 应对 |
|---|---|
| SQLite 迁移导致数据损坏 | 迁移前自动备份、双写/只读校验、失败回滚、保留 `data.json` |
| i18n 文案遗漏或键冲突 | 统一命名规范，增加“英文界面无中文残留”自动检查 |
| 更新签名密钥管理复杂 | 固定签名方案与发布流程，私钥离线保存，CI 仅持有公钥 |
| ASR 模型体积与授权 | 优先系统语音/本地小模型，做成可选下载组件 |
| Live2D 授权与包体 | 先 Lottie，Live2D 单独评估，不阻塞主版本 |
| 多平台适配成本 | 核心逻辑与平台能力解耦，按 Windows → macOS → Linux 推进 |
