# 自动裁剪规范（DeskPet v2.1+）

适用范围：设置页「导入单张图片」、批量导入八态图片、Codex 宠物逐帧替换、八态单图切割。
实现位置：`src/settings.html` 的 `PET_CROP` 常量表、`petImageAnalyze()` 与 `petImageSplitEight()`。
本文与常量表一一对应；改阈值必须同步改本文与第 6 节的验收数据。

## 1. 目标与边界

**做**：把素材四周的留白、透明区、导出时留下的棋盘格底色去掉，让角色在 120×112 的宠物框里占到合适比例。

**不做**（明确排除，避免误伤）：

| 不做的事 | 原因 |
| --- | --- |
| 抠图 / 去底色 | 白底、浅色描边与角色本体难以区分，误抠会吃掉轮廓 |
| 拆分 8×9 图集 | Codex 契约规定 8 列 × 9 行、行序固定，普通单图导入不拆格，随意拆分会让动画错位 |
| 拆分普通单图 | 只有专用「导入八态单图」入口按 4×2 固定规则切割；其他排版仍整幅保留 |
| 裁切动图 | GIF / APNG / 动态 WebP 逐帧裁切会丢帧或产生抖动 |
| 改画质 | 只做几何裁切与等比缩放，不重采样放大 |

## 2. 输入闸门（P0）

| 项 | 规则 | 常量 |
| --- | --- | --- |
| 类型 | `image/gif`、`image/png`、`image/webp`、`image/apng` | — |
| 体积 | ≤ 48 MB，超出直接拒绝并提示压缩 | `maxBytes` |
| 尺寸 | 长边 > 4096 时先等比缩到 4096，再分析 | `maxSide` |
| 尺寸无效 | 宽或高为 0 → 拒绝 | — |

归一化缩放比 \(s=\min\left(1,\ \dfrac{S_{\max}}{\max(w,h)}\right)\)，其中 \(S_{\max}=4096\)。后续所有坐标都在缩略图坐标系 \((s_w,s_h)\) 上计算，输出时再除以 \(s\) 还原到原图坐标。

## 3. 判定流水线

### P1 亮度

\[
v = 0.75\cdot(0.299R+0.587G+0.114B) + 0.25\cdot\frac{R+G+B}{3}
\]

视亮度占 3/4、灰度占 1/4，压低纯色相差异对「内容」判定的干扰，让「同亮度不同色」不被误判成内容。

### P2 透明度分流

抽样统计 `alpha < 250` 的像素数：

- 命中数 > 40 → 视为**已带透明通道**
- 否则 → 视为**实心底图**（走 P3~P5）

透明图（含棋盘格底导出痕迹）直接用 \(\alpha > 12\) 取包围盒。这里用「计数 > 40」而不是「存在一个半透明像素」，是为了跳过滤镜像素级的 alpha 噪点。

### P3 背景基调（仅实心底图）

先筛「低饱和浅色」像素：\(\min(R,G,B) > 200\) 且 \(\max-\min < 30\)。

- 若这类像素占比 > 15%：取亮度直方图**众数**作为背景基调 \(b\)
- 否则（深色 / 彩色底）：取全图亮度**中位数**作为 \(b\)

用众数而不是均值：棋盘格一格深一格浅，两色亮度接近时众数会收敛到同一个基调；均值会被深格拉偏。

### P4 行列投影

逐像素判断 \(|v-b| > 26\) 记为内容，得到每列 / 每行的内容像素计数 \(c_x\)、\(r_y\)，再按阈值切成连续区间：

\[
\tau_{\text{col}}=\max\left(2,\ \mathrm{round}(0.015\,s_h)\right),\qquad
\tau_{\text{row}}=\max\left(2,\ \mathrm{round}(0.06\,s_w)\right)
\]

- 列阈值 1.5%：横向只要有一小段内容就保留，避免裁掉伸出的手臂、尾巴
- 行阈值 6%：纵向更严，因为横向装饰线（分隔线、地平线）常贯穿整行，容易被误当内容

### P5 段内定框

在「列段 × 行段」的每个交叉格内统计内容像素数 \(n\)：

\[
n_{\min}=\max\left(64,\ \mathrm{round}\left(\frac{s_w s_h}{1500}\right)\right)
\]

\(n < n_{\min}\) 的格视为碎屑丢弃（噪点、孤立标点）。保留格的 **列段边界并集** 与 **行段边界并集** 构成裁框：

\[
\text{box}=\left[\min x_0,\ \min y_0,\ \max x_1,\ \max y_1\right]
\]

注意取的是「段边界」而非「像素极值」：这样同一列段内上下分离的两块内容（头与脚）也会被包进同一个框，不会被切成两半。

### P6 保护性短路（不裁）

按顺序判断，命中即整幅保留：

| 顺序 | 条件 | 结果说明 |
| --- | --- | --- |
| 1 | 短边 ≥ 1024、宽高比与 1536:1872 相差 ≤ 0.03、裁框仍覆盖 ≥ 85% 宽高 | 判定为 8×9 图集，整幅保留 |
| 2 | 动图（GIF / APNG / 前缀 VP8X 且 ANIM 位为 1 的 WebP） | 保留原图，避免丢帧 |
| 3 | 裁框距四边均 ≤ 2px | 已满幅，无需裁剪 |
| 4 | 找不到内容 / 整张透明 / 内容过少 | 报错，不产出空白图 |

图集阈值取 85%（而非 97%）是保守取舍：宁可少裁一次，也不能裁错格子导致行内动画错位。

### P7 输出

- 裁框四周各加 **4px** 透明内边距，避免描边被 CSS 投影切角
- 统一输出 PNG（`image/png` data URL），保留 alpha
- 同步回报：`width`、`height`、`cropped`、`crop{x,y,w,h}`、`coverage`、`note`

## 5. 与宠物窗口的衔接

裁剪结果写入皮肤条目的 `trim` 字段：

```
trim: { cropped: true, crop: {x, y, w, h}, note: '' }
```

宠物窗口据此：

- `trim.cropped` 为真时给 `#petImg` 加 `.trimmed`，`object-position: 50% 100%` 贴底对齐
- 单图形象按原比例 `object-fit: contain`，不再硬拉到 120×112
- 未裁剪的整幅图集（WebP / 动图）按单格比例摆放，不整张塞进宠物框

## 7. 已知局限

1. **不抠图**：棋盘格与角色交界的半透明边缘会作为内容保留；白底图的浅色描边可能被当背景。实心纯色 / 绿幕 / 蓝幕背景可先用设置页「智能去除背景」生成透明 PNG，再走本规范；去背景方案见 [`方案：将极简图片背景去除工具合并到 DeskPet.md`](方案：将极简图片背景去除工具合并到%20DeskPet.md)。
2. **弱对比素材**：角色与底色亮度差 < 26 时会被判成背景，此时报「没能识别出画面内容」而非产出错误裁切。
3. **横贯整行的装饰**：行阈值 6% 能滤掉细线，但粗横幅（> 6% 行高且贯穿全宽）仍会撑大裁框。
4. **单图与图集混用**：普通「导入单张图片」不会拆格；4 列 × 2 行八态单图必须走专用入口，其他非契约排版仍整幅导入——这是刻意行为，见第 1 节。

## 8. 八态单图切割（4×2 规则）

专用入口：设置页「导入八态单图（4×2 自动切割）」，只接收静态 PNG / WebP；动图、GIF、APNG 直接拒绝（逐格切割会丢帧）。

### 8.1 排版契约

| 项 | 规则 |
| --- | --- |
| 布局 | 4 列 × 2 行，共 8 个彼此分离的角色 |
| 读取顺序 | 按行读取：左上 → 右上，再左下 → 右下 |
| 状态顺序 | `idle / happy / sleep / work / click / drag / error / talk` |
| 背景 | 透明，或与自动裁剪相同的浅色棋盘格 / 纯色底 |
| 格内留白 | 允许，每格独立取内容包围盒 |
| 输出 | 8 张 PNG，统一画布，水平居中、底边对齐 |

### 8.2 切割流水线

1. 复用第 3 节 P1~P4：归一化、透明度分流 / 背景基调、行列投影。
2. 对列段 / 行段按内容像素总数排序，各取前 4 / 前 2 段，再按坐标排序（过滤边缘噪点形成的碎段）。
3. 在 4 × 2 交叉格内取内容包围盒；任一格内容少于碎屑阈值即报错，不产出缺状态的皮肤包。
4. 画布取 8 格内容的最大宽高，四周各加 4px 透明内边距；每格水平居中、底边对齐，避免状态切换时角色上下跳动。
5. 生成一个八态皮肤包条目，状态映射为 `idle.png` ~ `talk.png`，并写入 `sheet` 元数据（布局、顺序、源文件名、画布尺寸）便于追溯。

| `assets/examples/eight-state-4x2.webp` | 1536×1536，4 列 × 2 行 8 个角色 | 识别 4 列 × 2 行并切成 8 张 | 列段 `[64,391] [431,751] [768,1095] [1112,1511]`；行段 `[168,720] [849,1392]`；统一画布 408×561 |
